## 2. 培养目标与能力边界

### 2.1 初级嵌入式工程师目标

达到初级水平时，应能在指导较少的情况下：

- 使用 C 编写结构清晰、可编译、可调试的小型程序。
- 使用 Git、GCC、Make、GDB、交叉编译器和常用 Linux 命令。
- 看懂基础原理图、数据手册、引脚复用表和外设时序图。
- 在 M4 上完成 GPIO、UART、定时器、PWM、ADC、I2C、SPI、中断和 DMA 的基础开发。
- 使用 FreeRTOS 组织任务，并正确使用队列、信号量和互斥锁。
- 在 A7 Linux 上开发文件、线程、进程、网络和数据库应用。
- 修改设备树并实现基础字符设备或标准子系统驱动。
- 使用 remoteproc/RPMsg 完成 A7 与 M4 的基础通信。
- 对常见编译、运行、外设和通信故障进行有证据的定位。
- 完成需求、设计、编码、测试、文档和发布均完整的小型项目。

### 2.2 中级嵌入式工程师目标

达到中级水平时，应能进一步：

- 独立拆分需求、评估风险、设计模块边界和接口协议。
- 理解并修改 Bootloader、Kernel、设备树和根文件系统。
- 处理驱动并发、中断、DMA、内存、时钟、电源管理和性能问题。
- 设计可靠的多核系统，明确 A7/M4 资源归属和故障恢复策略。
- 实现版本管理、自动构建、日志、看门狗、参数保护、升级和回滚。
- 使用 GDB、strace、perf、ftrace、逻辑分析仪等工具定位跨层问题。
- 设计正常、边界、压力、断电、重启、断网和故障注入测试。
- 对稳定性、实时性、CPU、内存、启动时间和通信延迟给出量化结论。
- 主导一个中等复杂度嵌入式项目，并能解释关键设计取舍。

本路线中的“初级”和“中级”是能力里程碑，不等同于工作年限或企业职级。必须通过对应实战验收后才能标记达成。

## 5. 每次学习的固定流程

后续每次学习都按以下顺序执行：

1. **定位**：读取本文件和 `records/progress.md`，说明当前阶段、上次结果和本次唯一目标。
2. **预检**：确认前置任务、硬件、接线、工具和恢复措施满足要求。
3. **讲解**：只讲本次任务必需的原理，先建立概念图，再解释关键细节。
4. **预测**：运行代码或接线前，由学习者写下预期结果和可能失败点。
5. **实现**：由学习者完成最小可运行版本，保留构建命令和原始日志；教师只讲解和审阅，不代为操作。
6. **测量**：由学习者使用日志、GDB、系统工具、万用表或逻辑分析仪验证，并提交证据。
7. **故障注入**：教师布置安全的边界/异常测试，学习者亲自执行并记录结果。
8. **解释**：学习者用自己的话说明数据流、关键机制、错误路径和设计取舍。
9. **验收**：逐条核对标准并评分；未通过时生成补强任务，不直接进入下一阶段。
10. **归档**：更新实验报告、调试案例、本次任务记录、Git commit 和 `records/progress.md`。

每次学习以完成一个明确任务为边界：回顾必要前置知识，完成最小实现，进行测试和记录；不因时间到了就把未完成任务标记为完成。

## 6. 统一验收标准

### 6.1 实验完成定义

一个实验只有同时满足以下条件才算完成：

- **可构建**：从干净构建目录按记录命令成功构建，无未解释警告。
- **可复现**：只依据实验报告即可重新接线、编译、部署和运行。
- **可解释**：能说明关键代码、数据流、时序和失败路径，不依赖背诵教程原句。
- **可测量**：有日志、波形、寄存器、测试脚本或性能数据支撑结论。
- **可恢复**：失败不会永久卡死；阻塞操作有超时，错误有返回值和日志。
- **有异常测试**：至少覆盖正常、边界和异常三类情况。
- **可追溯**：代码、报告、证据和 commit ID 相互对应。

以下情况不通过：

- 只看课程或抄写笔记，没有独立输出。
- 复制厂商示例，无法解释或没有进行实质修改。
- 只有截图，没有源码、命令、原始日志和预期结果。
- 程序只在原目录偶然构建，清理后无法重建。
- 只测试正常路径，错误时只能重启。
- 学习者无法回答验收追问。

### 6.2 评分规则

每个实验和阶段均按 100 分评分：

| 维度 | 分值 | 评价重点 |
| --- | ---: | --- |
| 原理理解 | 20 | 能用自己的话解释机制和取舍 |
| 功能实现 | 25 | 需求完整、结果正确 |
| 调试与测量 | 20 | 用证据定位和验证，不靠猜测 |
| 异常与边界 | 15 | 超时、非法输入、断连、复位等行为明确 |
| 工程质量 | 10 | 分层、命名、错误处理、警告和资源释放 |
| 记录与复现 | 10 | 文档、版本、步骤、证据和提交完整 |

通过条件：

- 实验总分不低于 80 分。
- 功能实现不低于 18/25，调试与测量不低于 12/20，异常与边界不低于 9/15。
- 标记为“关键闸门”的项目必须全部通过，不能用其他得分补偿。
- 阶段考试首次未通过时，先补强薄弱项，至少间隔一次有效练习后再补考。

### 6.3 知识掌握等级

- L0 未接触：不知道概念或工具用途。
- L1 了解：能复述基本概念，但不能独立使用。
- L2 会用：参考文档能完成标准任务。
- L3 独立：能独立完成、调试并处理常见异常。
- L4 迁移：能用于新硬件/新需求，并解释取舍。

初级认证要求核心能力达到 L3；中级认证要求核心能力稳定达到 L3，至少 5 项达到 L4。

## 7. 学习前的设备与安全准备

### 7.1 必需设备

- FS-MP1A 开发板及符合产品手册要求的稳定电源。
- 产品手册规定的调试串口、数据线、网线和启动介质。
- 万用表。
- 至少 8 通道逻辑分析仪。
- 面包板、杜邦线、LED、限流电阻、按键、蜂鸣器。
- 至少一个 I2C 传感器和一个 SPI 外设；具体型号优先选择资料已有示例的器件。
- 可恢复系统的 TF 卡或其他介质。

示波器、可调电源、电子负载和独立调试器不是初始任务的必需品，但进入中级阶段前建议具备使用条件。

### 7.2 安全闸门

Linux 板卡的正常关机流程：登录板端后，以有权限的用户执行 `poweroff`，等待系统关机完成，再切断主电源；命令应在开发板 Linux 执行，不能误关 Ubuntu 开发主机。eMMC 上的可写文件系统在运行中直接断电可能丢数据或损坏文件系统；退出串口工具与执行 `sync` 均不能替代正常关机。板子不一定自动灭灯，应依据系统关机完成提示。具体镜像是否提供该命令、关机日志和实际断电流程尚待验证。

- 接线前查清供电电压、IO 电平、引脚方向和公共地。
- 断电接线，上电前用万用表检查短路和电源极性。
- 不将 RS-232 电平直接连接到 TTL UART。
- 不在未备份、未验证恢复流程时覆盖启动介质。
- 操作 GPIO 前检查该引脚是否已被 Linux、M4 或其他外设占用。
- 修改时钟、电源、DDR、分区和启动参数前保存原配置与完整串口日志。

### 任务 1.13：固定容量字节环形缓冲区（2026-10-20 至 2026-10-21，已通过）

- 目标是一个单线程 FIFO 字节队列，使用调用者提供的数组，不 malloc/free，不进行硬件接收，不宣称中断/多线程安全。
- 数据结构 ring_buf_t：uint8_t *data（借用存储）；size_t capacity（数组可用字节数）；size_t read_pos（下次读取下标）、write_pos（下次写入下标）、count（当前有效字节数）。使用 <stdint.h> 和 <stddef.h>。
- 空队列 count == 0；满队列 count == capacity，全部 capacity 个字节可用，不预留空槽。成功操作后下标到末尾需回绕；禁止越界，满时不覆盖旧数据，空时不读取旧数据。数据字节 0 有效，不能用字节值 0 代表空队列。
- int rb_init(ring_buf_t *rb, uint8_t *storage, size_t capacity)：rb/storage 非 NULL、capacity > 0；调用者保证 storage 实际至少有 capacity 字节。成功绑定数组，两个下标和 count 设为 0，返回 0；参数非法返回 -1，保持可访问的 rb 原有成员及数组不变。无需清零数组，允许初始化尚未初始化的可写结构体，不读取其旧成员。
- int rb_push(ring_buf_t *rb, uint8_t value)：调用者须先成功初始化；rb == NULL 返回 -1；队列满返回 -2；成功入队一个任意字节（含 0）返回 0，更新写下标与 count，不改变 read_pos。失败不得修改队列成员或存储内容。
- int rb_pop(ring_buf_t *rb, uint8_t *out)：调用者须先成功初始化，非 NULL 的 out 须指向可写字节且不与队列结构/存储重叠；rb/out == NULL 返回 -1；队列空返回 -2；成功将最早字节写入 *out、更新读下标与 count，返回 0，不改变 write_pos。失败队列与 *out 均不变；不要求擦除已读字节。
- 存储所有权由调用者保留，队列使用期间 storage 必须一直有效；不能返回借用已结束生命周期局部数组的队列。重新初始化表示丢弃原逻辑数据，不释放或清零数组。
- 本次一次布置三个函数，不拆成逐行往返；按源码审阅，覆盖容量 1/非 2 的幂、填满拒绝、清空拒绝、回绕 FIFO、非法参数不改状态。函数通过后不索取或保留逐项测试日志，不代写实现、不代建工程。完整学习过程和契约保存在对应 sessions 记录。
- 2026-10-21 首轮源码审阅发现 `rb_init` 成功路径漏设 `rb->capacity`；学习者随后提交修正版，已加入 `rb->capacity = capacity`。结合此前 `rb_push/rb_pop`，三个函数源码审阅全部通过，100/100。合法初始化会建立 capacity > 0、count/read/write_pos 为 0 的不变量；push/pop 在该不变量下正确处理满/空、FIFO、回绕和错误不改状态。按约定未要求或保留逐项测试日志，不声称已编译/运行。
