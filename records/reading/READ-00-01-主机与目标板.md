## 今天的目标

区分开发主机和目标板，理解为什么嵌入式程序经常需要“交叉编译”。

## 两个角色

- **开发主机**：你用来写代码、编译和调试的电脑。你的开发环境是 Ubuntu 26.04。
- **目标板**：最终运行程序的设备。本路线的目标板是 FS-MP1A，运行程序的处理器架构与普通 Windows PC 不同。

程序要经过这条路径：

```text
源代码
  → 在开发主机上用合适的编译器构建
  → 生成适合目标板处理器和系统的程序
  → 传到目标板
  → 在目标板上运行
```

编译器不只是“名字不同”，还会决定生成程序使用的 CPU 指令集、二进制格式、调用约定/ABI，以及目标系统需要的运行时和动态加载器。FS-MP1A 上的 Cortex-A7 运行 Linux，因此板端应用必须与目标系统的 ARM ABI、ELF 格式和库环境兼容。**交叉编译**就是在一台机器上，使用面向另一种处理器/系统的工具链来构建程序。

此前查到的 MinGW GCC 属于助手的 Windows 执行环境，不代表你的 Ubuntu 工具状态。你的 ARM 交叉编译环境尚待在 Ubuntu 中核实。是否能运行在目标板上，要检查生成文件架构并由你实际部署验证。

## 小检查

请用自己的话回答，不需要背定义：

1. 学习者回答：开发主机写代码、编译生成可执行二进制，烧录到目标板；目标板实现相应功能。
   - 评价：核心职责理解正确。Linux 用户态应用通常复制到板端文件系统后执行；写入 Flash/启动介质的“烧录”主要用于固件或系统镜像，具体看部署对象。
2. 学习者回答：编译器不同。
   - 评价：方向正确但不完整。需要进一步指出目标 CPU 指令集、二进制格式、ABI/运行时库不兼容。
3. 学习者回答：首先检查复位和时钟。
   - 评价：对于板卡无法启动、外设不工作等问题可能相关，但不是可执行文件报格式错误/无法执行时的优先检查。应先检查文件格式和目标架构，再检查动态加载器/库依赖与执行权限。

说明：Linux 常见的 `Exec format error` 优先指向可执行格式或架构不匹配；`No such file or directory` 在文件明明存在时也可能是 ELF 指定的动态加载器缺失。复位和时钟属于系统启动、硬件初始化或外设时序的诊断方向。
