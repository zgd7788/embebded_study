### 2.2 地址、MAP和数据的区别

| 数值 | 所属概念 | 当前含义 |
|---|---|---|
| `0x4A` | 7位器件地址 | AD0=0时选择本器件；传给当前I²C接口的是此原始地址 |
| `0x94` | 线上地址字节 | `0x4A << 1`，R/W=0，主机请求写 |
| `0x95` | 线上地址字节 | `(0x4A << 1) \| 1`，R/W=1，主机请求读 |
| `0x01` | MAP字节示例 | INCR=0，内部寄存器指针选择0x01 |
| `0x81` | MAP字节示例 | INCR=1，内部寄存器指针从0x01开始并自动递增 |
| `0xD9` | 数据字节示例 | 当前芯片0x01寄存器的读取结果，不是器件地址或应答信号 |

MAP的布局在第44页图24、图25中表示为：

```text
bit7       bit6 ... bit0
INCR       寄存器地址

0x81 = 0x80 | 0x01
       开启自增  起始寄存器
```

发送MAP是设置器件内部的访问指针。只发送MAP后就STOP，不会把MAP字节本身写成所选寄存器的数据；要更新寄存器内容，还须继续发送数据字节。

芯片按字节在事务中的位置识别它的用途：一次写事务的器件地址之后，第一个数据字节就是MAP，后面的字节才是所选寄存器的数据。因此，设置MAP不需要先发送另一项“MAP寄存器地址”。

```text
仅选择读取起点并开启自增：
器件写地址0x94 → MAP=0x81 → STOP

向ADCA衰减寄存器写入FF：
器件写地址0x94 → MAP=0x0C → 数据0xFF → STOP
```

省略图中应答仅用于对比字节角色。前者只有MAP，没有随后的待写数据，原有功能寄存器内容保持不变；后者的FF才进入0x0C寄存器。随后独立读事务不含寄存器地址字节，芯片按此前保存的MAP指针输出数据；MAP=0x81使本例的数据来源依次为0x01、0x02、0x03。

### 2.3 当前连续读取对应的规则

依照第44页图25，本例使用两个独立事务：

```text
设置指针：
START → 写地址0x94 → 从机ACK → MAP=0x81 → 从机ACK → STOP

接收三个字节：
START → 读地址0x95 → 从机ACK
      → 数据D9 → 主机ACK
      → 数据00 → 主机ACK
      → 数据AE → 主机NACK → STOP
```

| 寄存器地址 | 第46页列出的默认值 | 本例意义 |
|---|---|---|
| `0x01` | `0xD9` | ID与修订号，实际修订号可不同 |
| `0x02` | `0x00` | Power Control 1 |
| `0x03` | `0xAE` | Speed Control & Power Control 2 |

`MAP.INCR`决定从机是否切换到下一个寄存器；STM32的`NBYTES`决定主机接收多少字节。二者分别配置，不能相互代替。数据值AE本身没有“结束标记”的含义。

图25末尾的NO ACK就是最后一个数据字节后的NACK。当前例程的接收数量配置与自动结束机制见下文STM32部分。

寄存器控制口读写验证与完整音频启动、PCM传输是不同任务。复位、软件模式选择和音频时钟的完整要求应结合第41、42页重新核对，不能仅凭ID可读就认定音频已经初始化。

### 3.4 本次复盘容易混淆的地方

- `NACKF`记录收到对方的NACK；主机读末字节时主动发送的NACK是正常结束，不因这一正常应答而置主机的NACKF。
- `uint32_t status = I2Cx->ISR`是C语言数值复制。随后写ICR清硬件标志，不会改变已经保存的status；这个变量不是寄存器别名。
- `received`是软件已从RXDR取出的数量；NBYTES对应硬件传输计数。硬件不依赖软件执行`++received`来决定末字节应答。
- RXNE与STOPF可能同时被软件观察到，应先取末字节，再核对STOP及数量。
- NACK不能单独定位故障原因，可能来自地址无应答、器件未就绪或器件拒收数据；需结合阶段、供电、复位、接线和器件协议分析。
