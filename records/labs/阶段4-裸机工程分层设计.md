# 阶段4 裸机工程分层设计建议

日期：2026-11-24。学习者希望将不同层级的代码分开，方便后续维护与迁移。本文件为针对 project/stage_4/261122 的设计建议；学习者随后已迁移目录，最新实际结构、构建问题及检查证据见末尾“目录迁移审阅”，前文为实施前的设计过程。

## 目录与职责

建议优先按职责组织，当前规模可将同一模块的 .h/.c 放在一起，后续文件增多再在各层内部拆分 inc/src。

```text
261122/
├── app/
│   └── main.c
├── board/
│   └── fsmp1a/
│       ├── board.h
│       ├── board.c
│       └── board_timebase.c
├── drivers/
│   ├── mcu/
│   │   ├── gpio.h / gpio.c
│   │   ├── rcc.h / rcc.c
│   │   ├── uart.h / uart.c
│   │   ├── gtim.h / gtim.c
│   │   └── i2c.h / i2c.c
│   └── devices/
│       ├── buzzer.h / buzzer.c
│       └── cs42l51.h / cs42l51.c
├── platform/
│   └── timebase.h
├── start/
│   └── start.S
├── linker.ld
├── Makefile
├── README.md
└── build/
```

其中 board 模块、cs42l51 模块为后续新增，board_timebase.c 是当前 timebase.c 后续调整的归属；目标目录示意不表示所有文件已存在。

| 部分 | 职责与约束 |
|---|---|
| app | 验证流程、数据比较及应用行为；通过器件接口操作 CS42L51，应用专题仍可直接调用待学习的 MCU 驱动 |
| board/fsmp1a | 具体引脚、AF、时钟、I2C5/地址0x4A/复位PC0等资源绑定和初始化顺序，将器件需要的板级配置交给器件驱动 |
| drivers/mcu | GPIO、RCC、UART、TIM、I²C 等片上外设的寄存器访问；不依赖应用或音频芯片协议 |
| drivers/devices | 蜂鸣器、CS42L51 等器件行为与协议；通过下层外设接口访问硬件，音频芯片寄存器和 MAP.INCR 在此解释 |
| platform/timebase.h | 提供公共 tick 读取契约，约定频率、回绕及启动前提，面向使用者隐藏具体定时器 |
| board_timebase.c | 实现公共时间接口并绑定当前 TIM2，调用 MCU 定时器驱动；初始化频率与使用者的超时单位保持一致 |

## 依赖边界

典型运行路径为 app → devices/cs42l51 → mcu/i2c → 寄存器。board 负责组装资源及初始化，可以调用两类驱动；底层驱动不得反过来调用 board 初始化或 main。board 是资源装配位置，并非强制要求每次器件访问都必须经过的中转层。

时间源作为公共能力单独处理：I²C/UART 只依赖时间接口声明，板级实现选择 TIM2 并使用 gtim 完成读取。当前 Timebase_GetTicks 仍接收 gtim_t 指针，timebase.h 包含 gtim.h，I²C/UART 还直接传 TIM2；目录迁移本身不能消除这些依赖，应在后续单独整理接口和调用处。无需在本次目录讨论中同时扩展回调框架或操作系统适配。

## 迁移顺序

1. 先按职责迁移已有模块，保持函数行为；同步 Makefile 的源文件路径、头文件搜索路径及 VS Code 配置。
2. 构建检查通过后，逐步将 main 中的板级初始化、资源绑定收拢到 board，将芯片寄存器协议收拢到 cs42l51。
3. 单独调整公共时间接口，统一声明、实现、调用及注释，明确 tick 单位不变。

按步骤复用现有例程验证变化，不将目录整理或编译通过直接视为运行功能通过。本轮没有代码修改、编译或板端测试；明天仍先理解已有多字节接收实现。

## 面向后续项目的文件维护规则

学习者进一步询问从资深嵌入式工程师视角，如何培养项目文件管理习惯。以下规则为建议，尚未实施目录或源码迁移。

### 按职责组织，随实际规模扩展

沿用 app、board、drivers/mcu、drivers/devices、platform、start 的职责划分。名称也可采用 BSP 等团队约定，但同一项目应固定含义；不额外建立职责重复的 board/bsp 两套目录。func 不是统一标准，如果具体模块已经明确为命令处理、协议解析或音频控制，优先使用 console、protocol、audio 等可辨识名称。当前没有实际模块时不提前建立 services 等空层次。

同一个模块的 .h/.c 默认相邻；例如后续 CS42L51 文件增多时放 drivers/devices/cs42l51/，模块较小时直接放 drivers/devices/ 即可。各层可在规模确有需要时再拆内部 inc/src。当前学习工程不要求同时完成全部目标目录。

### 模块边界及头文件

每个文件围绕一项职责，应用流程、板级初始化、器件协议和外设寄存器访问分别归属。驱动不依赖 main 或应用命令处理，也不因芯片传输失败直接承担应用串口输出；应用决定如何报告错误。板级代码负责组装资源，允许调用 MCU 与器件驱动。

头文件公开外部使用者真正需要的类型、声明和常量，内部辅助函数优先 static；不在公共头文件定义可变全局对象。不能因目录分开就声称消除了依赖，当前 timebase 暴露 gtim_t/TIM2 仍须后续独立整理。约定的公共接口须明确超时单位、初始化前提和失败后输出是否可用。

避免逐渐增长为混杂存放所有宏、变量与函数的 common.h、utils.c、func.c。通用模块应有可描述的共同职责，例如时间服务、CRC 或环形缓冲区。

### 配置归属

- MCU 寄存器地址、布局和位定义：MCU 驱动。
- 引脚、AF、板载复位连接、总线实例和器件地址绑定、时钟及初始化顺序：board/fsmp1a。
- CS42L51 寄存器地址、MAP.INCR 和器件行为：器件驱动。
- 例程测试值、测试长度和应用策略：app。

共享硬件资源还须注明使用者，例如当前 TIM2 是 UART/I²C 超时的公共时间源，其他模块不能擅自重配其频率。后续增加中断/DMA时按实际分配维护 IRQ、DMA 通道等资源表，本轮不设计未学模块。

### 命名和构建

目录及源文件统一使用有意义的英文命名和一致风格，避免 test1.c、new.c、最终版2.c 等长期留存。构建从工程根目录执行，路径相对工程根目录；编译器、源文件清单、头文件路径、启动文件、链接脚本和必要选项可从版本库恢复。实际构建和编辑器的工具链与头文件搜索路径保持一致。头文件重名要通过清楚的模块命名和精确搜索路径解决，不能仅依赖编辑器递归扫描整个工作区。

迁移时同步 Makefile、include 搜索路径、编辑器配置和文档。后续补全 Makefile 的头文件依赖追踪，保证头文件变化触发相应重编译；当前尚未修改。产物集中在 build，使用相对路径保留对象文件的目录结构，避免同名源文件生成同名对象相互覆盖。

### 版本与产物

日期工程适合保留学习阶段的独立例程；持续维护的正式产品通常使用一个主工程，通过 Git 提交、标签记录版本，避免复制多份最新工程并行维护。同一复用模块保持明确的维护来源，学习快照保留其独立性，不将旧例程无意绑定到会继续变化的共享文件。

自研源码、公共头文件、构建及链接脚本、可共享配置和文档应纳入版本控制；普通生成物、缓存及机器专用路径不作为源码管理。厂商库有明确目录、版本和许可证，必要修改留记录。发布 BIN/ELF 可作为独立发布产物保存，并附对应源码提交号、工具链和构建配置，避免失去与来源的对应关系。

当前仓库 .gitignore 整体忽略 .vscode，规则未修改。后续如需共享编辑器构建/调试配置，应区分可共享模板与个人绝对路径，再明确调整忽略策略。此建议不代表已更改 Git 策略、暂存、提交或推送。

### 文档与验证材料

README 保留用途、硬件前提、构建/加载命令及正常输出；硬件资源映射、设计取舍、关键问题另按主题记录，避免同一配置在多处重复维护。学习过程继续放 records，项目稳定说明放工程 README 或按需增加 docs，目标目录不要求立即创建。

有实际验证材料时，可按主机测试和板端例程区分放置，并注明验证对象、输入、预期和实际结果。模拟测试与板端输出分别记录，避免测试代码混入正式镜像；目录迁移与功能重构分步提交和验证，保留可定位变化范围。无需为低影响文件整理机械新增测试。

当前实施优先级：先统一职责与目录，再迁移现有模块并保持构建，通过后逐步整理 board、器件封装与时间接口。此顺序属于建议，下一轮具体任务由学习者决定。
