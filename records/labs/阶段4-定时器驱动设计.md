## 计划接口

| 接口 | 职责与副作用 |
|---|---|
| TIM_BaseInit | 配置共享计数基础并保持停止；初始化会影响该定时器全部通道的时间条件，须独占配置 |
| TIM_Start / TIM_Stop | 仅管理计数启动与停止；停止不清除配置 |
| TIM_GetCounter / TIM_SetCounter | 显式读写计数值；写入会影响所有通道和依赖它的时间源 |
| TIM_IsUpdatePending | 仅查询更新标志，不清除 |
| TIM_ClearUpdateFlag | 仅清除更新标志 |
| TIM_GenerateUpdate | 显式产生软件更新事件；相关预装载及计数副作用按手册讲解后实现，不作为比较值更新的隐藏动作 |
| TIM_PWM_ConfigChannel | 配置指定CH1～4的PWM模式、极性、预装载和初始比较值，完成后该通道保持关闭；要求目标计数器已停止、基础初始化完成，其他通道配置不变；最终更新装载在启动前显式安排 |
| TIM_PWM_Start | 开启指定通道输出并启动共享计数器；若已计数，不强制清零，不保证从周期起点加入 |
| TIM_PWM_Stop | 仅关闭指定通道输出，不停止可能被其他通道共享的计数器 |
| TIM_PWM_SetCompare | 修改指定通道比较值，不重置CNT、不改PSC/ARR、不隐式产生UG；预装载生效时间写入接口契约 |

后续依次设计输入捕获ConfigChannel/Start/Stop/ReadCapturedValue，以及中断、DMA、死区/刹车等所需功能。统一命名不等于所有实例支持所有功能，按实例能力和位宽检查；具体寄存器布局不可直接跨类别套用。

## 输入捕获接口设计（2026-11-17，待学习者实现）

以现有TIM2～5驱动为基础，沿用gtim_t与gtim_channel_e，输入捕获接口暂在gtim.h/c按职责组织，不新增空框架。以下是设计建议，尚无相应定义、实现、构建或实测证据。

| 接口 | 职责 |
|---|---|
| TIM_IC_ConfigChannel | 校验并配置指定通道的输入映射、边沿、滤波与捕获预分频；要求目标计数器停止且基础初始化完成，完成后该通道保持关闭；不修改其他通道或共享PSC/ARR/CNT，不隐式UG |
| TIM_IC_Start | 开启已配置的捕获通道，并开启共享计数器；不清CNT，不隐式UG；多通道测量时先全部配置，再按启动契约使能 |
| TIM_IC_Stop | 仅关闭指定捕获通道，保留共享计数器运行与其他通道 |
| TIM_IC_ReadCapturedValue | 非阻塞读取并消费捕获结果，通过状态区分无数据、新捕获、过捕获和参数/模式错误，通过输出参数返回原始计数；不在驱动内计算频率、周期或占空比 |

配置结构体暂命名gtim_ic_config_t，包含Selection（直接/间接映射）、Edge（上升沿/下降沿）、Prescaler（每1/2/4/8个有效边沿捕获）、Filter（ICxF原始编码0～15）；暂不扩展TRC和双边沿捕获。枚举可采用软件语义值，由驱动显式映射硬件编码。捕获值由硬件写入CCR，不在此配置中设置CompareValue。保留RCC、GPIO、基础计数及测量应用的职责边界，定时器频率和tick换算由上层结合真实计时配置处理。

学习者询问三个枚举怎样定义后，给出可供其采用的定义示例，沿用头文件现有gtim_select_e、gtim_captureedge_e、gtim_prescaler_e类型名。建议常量分别为TIM_IC_SELECT_DIRECT/INDIRECT=1/2（CCxS未移位编码01/10）、TIM_IC_EDGE_RISING/FALLING=0/1（当前仅单边沿，对应CCxP且CCxNP须保持0）、TIM_IC_PSC_DIV1/DIV2/DIV4/DIV8=0/1/2/3（ICxPSC未移位编码）。这些具体取值恰与当前支持的字段编码对应；名称表示功能选择，数值不是完整寄存器值，仍需校验、目标通道定位和字段移位。DIV4的枚举值2表示编码10，不表示除2。此为对话中的示例，尚未替学习者写入源码或验收采用情况。

当前只要求学习者定义配置类型并提交审阅，不要求一次实现全部接口。具体返回码、首次启动旧标志处理、读取与过捕获竞态/恢复契约在相应函数实现前明确；此处的职责表不能作为已可并发安全读取的证明。

### 启停与剩余接口首轮审阅后的契约建议（2026-11-17）

当前学习者已采用上述枚举与gtim_ic_config_t，已实现Start/Stop，配置函数尚只有声明，读取函数为空函数体，不能把前述“待实现”一概视为当前全部未开始。首轮源码审阅：Stop符合关闭目标通道、保留共享计数器的职责；Start须在任何写操作前确认目标CCxS为当前支持的01或10，不能误使能仍为输出模式的通道。

- TIM_IC_ConfigChannel建议返回int，参数为gtim_t *TIMx、gtim_channel_e channel、const gtim_ic_config_t *config。仅配置目标捕获通道，保持关闭；调用方先开启时钟、完成BaseInit并停止计数，配置期间独占硬件。Selection须为DIRECT/INDIRECT，Edge须为RISING/FALLING，Prescaler须为DIV1/2/4/8，Filter为0～15。返回0成功、-1参数非法、-2合法参数但计数器仍运行，全部校验完成前不写硬件。目标通道关闭后再改CCxS，不写共享PSC/ARR/CNT或其他通道，不隐式UG。
- TIM_IC_Start：0成功、-1实例/通道非法、-2目标未配置为当前支持的直接/间接输入；失败不写硬件。成功只开目标CCxE及共享CEN，不清CNT、不隐式UG。时钟/GPIO和基础初始化由调用方保证；清除旧捕获状态的归属及首次启动边界在配置/启动实现前进一步落实。
- TIM_IC_Stop：0成功、-1实例/通道非法，失败不写硬件；成功仅关目标CCxE，不关共享CEN，不清其他通道标志。当前源码符合此局部契约，需补齐注释。
- TIM_IC_ReadCapturedValue建议返回int，参数为gtim_t *TIMx、gtim_channel_e channel、uint32_t *capture。实例仅TIM2～5、通道CH1～4，capture须非空可写；调用方开启时钟并独占通道结果的消费。非阻塞获取指定通道原始捕获计数，返回1有新捕获、0无新捕获、-1参数非法、-2目标不是当前支持的捕获输入、-3过捕获。仅返回1时capture提供有效新结果，合法捕获值0不表示错误；不在该函数计算周期/频率。声明与定义必须一致。非法参数/模式不得消费CCR或修改寄存器；正常读取和过捕获恢复的竞态与清标志细节在实现前补讲，不因定好原型就声称读取可靠。

### 非阻塞读取约定（2026-11-21）

调用方开启目标时钟，并独占目标通道的配置和捕获结果读取。复用 `tim_channel_registers` 与 `tim_channel_is_capture`：实例、通道或空输出指针非法返回 -1；`CCxS` 非当前支持的 01/10 返回 -2。这两种路径不消费捕获或改写寄存器。检查模式不要求当前 `CEN`、`CCxE` 为 1，已停止的通道也可能仍有待取结果。

CH1～4 的 `CCxIF` 位依次为 1～4、`CCxOF` 为 9～12；对应 CH1 的掩码左移通道索引 0～3，不能使用 CCMR/CCER 移位。先读 `SR`，两个目标标志都未置位返回 0；`CCxIF` 置位时读取一次目标 `CCR` 到局部变量，由读取动作清 `CCxIF`。读取后复查 `CCxOF`，用于发现首次检查 `SR` 与读取 `CCR` 之间的覆盖。只要读取前或复查发现过捕获，就不交付该次样本，按 `rc_w0` 规则清目标 `CCxOF` 后返回 -3；即使首次检查仅见 `CCxOF` 也需报告。禁止用 `SR &= ~mask` 清除标志，以免误清读写之间新置位的其他状态；勿在读取 `CCR` 后再手动清 `CCxIF`。仅在返回 1 时写输出指针，计数值 0 也合法。上层收到 -3 后丢弃原有边沿配对，重新采集连续有效样本；该方案用于单消费者轮询，不保证任意输入速率下无丢失。

## 设计规则

当前位掩码清单（2026-11-15）：

| 寄存器 | 当前实际使用的字段与位位置 |
|---|---|
| CR1 | CEN=0，UDIS=1，URS=2，OPM=3，DIR=4，CMS=6:5，ARPE=7，UIFREMAP=11 |
| SMCR | SMS=2:0和16（不连续），ECE=14 |
| SR / EGR | UIF=0 / UG=0 |
| CCMR的CH1基准 | CC1S=1:0，OC1FE=2，OC1PE=3，OC1M=6:4和16（不连续），OC1CE=7 |
| CCER的CH1基准 | CC1E=0，CC1P=1，CC1NP=3 |

以上用#define定义GTIM_寄存器_字段_Msk。模式值另命名，PWM1/PWM2编码分别为6/7，基准移位4。CH2～4按已记录通道映射平移，不必复制四套配置代码。当前整值写入PSC/ARR/CCR使用范围校验，不为了形式统一新增无用掩码。宏不改变寄存器写语义，状态清除和事件产生仍按手册处理。

寄存器位按需命名，例如当前gtim.h中定义GTIM_CR1_CEN_Msk为(1U<<0U)，Start/Stop/运行检查复用同一掩码。同样方法逐步覆盖ARPE、UIF、UG等实际使用字段；不要求一次搬全芯片寄存器宏。共享硬件定义可放寄存器头文件，驱动私有定义可放内部头文件或.c顶部，当前不为文件分层额外改目录。位掩码是常量，不另建软件变量代替硬件CEN状态。

实例选择硬件，通道参数选择CH1～4，配置结构体表达功能需求。一个定时器内部的计数基础是共享资源，配置通道不应顺便重设其他用户依赖的PSC/ARR。查询与清除分开；参数校验完成前不写寄存器。配置和Start分开；每次Init或SetCounter/GenerateUpdate的全局副作用必须显式说明。

所有需报错的接口使用有文档约定的状态码，读数据时若需报告非法参数则使用返回状态加输出指针，不用合法数据0假冒错误。具体原型、状态码、计数范围和100%占空比边界在对应实现前逐项明确，不先填充全部接口。编译时同步声明、定义、全部调用点与构建清单。

## 当前第一项：配置类型

1. tim_channel_t：CH1～CH4，公共语义编号1～4，驱动内部转换成对应字段，不把编号直接当寄存器掩码。
2. tim_pwm_mode_t：PWM1/PWM2，公共语义值1/2，驱动内部转换为寄存器编码，不直接左移枚举值写OCxM。
3. tim_polarity_t：高有效/低有效，分别取0/1，明确名称含义。
4. tim_pwm_config_t：Mode、Polarity、Compare；Compare使用uint32_t以容纳不同实例的比较值，合法范围按实例及当前周期在实现时说明。

本轮由学习者定义这些类型；暂不实现PWM2以外的复杂模式，不引入通用回调、动态分配或框架。下一步明确TIM_PWM_ConfigChannel的参数、失败行为、停止前提及字段映射后实现。已有CH1寄存器片段作为复用基础，不自动标记通用CH1～4配置已完成。
