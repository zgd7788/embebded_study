## 计划接口

| 接口 | 职责与副作用 |
|---|---|
| TIM_BaseInit | 配置共享计数基础并保持停止；初始化会影响该定时器全部通道的时间条件，须独占配置 |
| TIM_Start / TIM_Stop | 仅管理计数启动与停止；停止不清除配置 |
| TIM_GetCounter / TIM_SetCounter | 显式读写计数值；写入会影响所有通道和依赖它的时间源 |
| TIM_IsUpdatePending | 仅查询更新标志，不清除 |
| TIM_ClearUpdateFlag | 仅清除更新标志 |
| TIM_GenerateUpdate | 显式产生软件更新事件；相关预装载及计数副作用按手册讲解后实现，不作为比较值更新的隐藏动作 |
| TIM_PWM_ConfigChannel | 配置指定CH1～4的PWM模式、极性、预装载和初始比较值，完成后该通道保持关闭；要求目标计数器已停止、基础初始化完成，其他通道配置不变；最终更新装载在启动前显式安排 |
| TIM_PWM_Start | 开启指定通道输出并启动共享计数器；若已计数，不强制清零，不保证从周期起点加入 |
| TIM_PWM_Stop | 仅关闭指定通道输出，不停止可能被其他通道共享的计数器 |
| TIM_PWM_SetCompare | 修改指定通道比较值，不重置CNT、不改PSC/ARR、不隐式产生UG；预装载生效时间写入接口契约 |

后续依次设计输入捕获ConfigChannel/Start/Stop/ReadCapturedValue，以及中断、DMA、死区/刹车等所需功能。统一命名不等于所有实例支持所有功能，按实例能力和位宽检查；具体寄存器布局不可直接跨类别套用。

## 设计规则

当前位掩码清单（2026-11-15）：

| 寄存器 | 当前实际使用的字段与位位置 |
|---|---|
| CR1 | CEN=0，UDIS=1，URS=2，OPM=3，DIR=4，CMS=6:5，ARPE=7，UIFREMAP=11 |
| SMCR | SMS=2:0和16（不连续），ECE=14 |
| SR / EGR | UIF=0 / UG=0 |
| CCMR的CH1基准 | CC1S=1:0，OC1FE=2，OC1PE=3，OC1M=6:4和16（不连续），OC1CE=7 |
| CCER的CH1基准 | CC1E=0，CC1P=1，CC1NP=3 |

以上用#define定义GTIM_寄存器_字段_Msk。模式值另命名，PWM1/PWM2编码分别为6/7，基准移位4。CH2～4按已记录通道映射平移，不必复制四套配置代码。当前整值写入PSC/ARR/CCR使用范围校验，不为了形式统一新增无用掩码。宏不改变寄存器写语义，状态清除和事件产生仍按手册处理。

寄存器位按需命名，例如当前gtim.h中定义GTIM_CR1_CEN_Msk为(1U<<0U)，Start/Stop/运行检查复用同一掩码。同样方法逐步覆盖ARPE、UIF、UG等实际使用字段；不要求一次搬全芯片寄存器宏。共享硬件定义可放寄存器头文件，驱动私有定义可放内部头文件或.c顶部，当前不为文件分层额外改目录。位掩码是常量，不另建软件变量代替硬件CEN状态。

实例选择硬件，通道参数选择CH1～4，配置结构体表达功能需求。一个定时器内部的计数基础是共享资源，配置通道不应顺便重设其他用户依赖的PSC/ARR。查询与清除分开；参数校验完成前不写寄存器。配置和Start分开；每次Init或SetCounter/GenerateUpdate的全局副作用必须显式说明。

所有需报错的接口使用有文档约定的状态码，读数据时若需报告非法参数则使用返回状态加输出指针，不用合法数据0假冒错误。具体原型、状态码、计数范围和100%占空比边界在对应实现前逐项明确，不先填充全部接口。编译时同步声明、定义、全部调用点与构建清单。

## 当前第一项：配置类型

1. tim_channel_t：CH1～CH4，公共语义编号1～4，驱动内部转换成对应字段，不把编号直接当寄存器掩码。
2. tim_pwm_mode_t：PWM1/PWM2，公共语义值1/2，驱动内部转换为寄存器编码，不直接左移枚举值写OCxM。
3. tim_polarity_t：高有效/低有效，分别取0/1，明确名称含义。
4. tim_pwm_config_t：Mode、Polarity、Compare；Compare使用uint32_t以容纳不同实例的比较值，合法范围按实例及当前周期在实现时说明。

本轮由学习者定义这些类型；暂不实现PWM2以外的复杂模式，不引入通用回调、动态分配或框架。下一步明确TIM_PWM_ConfigChannel的参数、失败行为、停止前提及字段映射后实现。已有CH1寄存器片段作为复用基础，不自动标记通用CH1～4配置已完成。

## ConfigChannel实现契约补充

本日最新枚举约定：学习者已将TIM_PWM_MODE_1/TIM_PWM_MODE_2改为0/1，ConfigChannel仍按名称校验并显式映射到硬件编码6/7，沿用此实现即可。下文6/7公共枚举属于此前源码快照。_Msk负责字段范围，PWM1/PWM2配置宏负责写入编码，不能用掩码本身表示模式选择。

源码中的类型实际命名为gtim_channel_e、gtim_pwm_mode_e、gtim_polarity_e、gtim_pwm_config_t；通道值为0～3、模式值为6/7。上述1～4及1/2属于先前设计建议，当前采用源码的合法值并在驱动显式映射，不强制为编码风格更改公共值。

TIM_PWM_ConfigChannel返回int，接收实例、通道、const配置指针。成功0、参数错误-1、计数器已运行-2，所有检查先于硬件写入；时钟已开且已基础初始化由调用方保证。Compare按CCR位宽校验，保持原始计数值语义，允许大于ARR，百分比接口另行设计。先选择CCMR/CCR及移位，再共用模式配置逻辑，保持其他通道与共享计数配置不变。普通PWM关闭快速响应OCxFE和外部清除OCxCE，配置后仍不启动计数或通道，也不产生UG；加载预装载由后续显式更新事件完成。
