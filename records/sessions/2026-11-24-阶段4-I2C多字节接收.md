## 本次目标与器件依据

接续多字节接收，先由学习者实现独立读事务接口：

```c
int I2C_MasterRead(i2c_t *I2Cx, uint8_t addr7, uint8_t *data,
                   size_t length, uint32_t timeout_ticks);
```

当前仅支持 I2C5、原始 7 位地址、非空且至少 length 容量的可写缓冲区、1～255 字节长度。首版 RELOAD=0、AUTOEND=1；长度不含线上从机地址，整笔访问共用超时预算。返回 0 表示接收长度满足、正常 STOP 且未收到 NACK，-1 参数无效、-2 超时、-3 从机 NACK 后 STOP、-4 STOP 时数量不符。用 received 记录已从 RXDR 取出的字节数，每次 RXNE 读取一个字节。必须先处理 RXNE 再判断 STOP，避免末字节与 STOPF 同时置位时遗漏数据。失败时缓冲区可能包含本次已接收的部分字节，输出不提供回滚保证，调用方只能在返回 0 后使用完整结果，不提前实现复制暂存框架或额外堆分配。

本轮核对 CS42L51 DS679F1 第 45 页第 4.10.3/4.10.3.1 节：MAP 字节低七位选寄存器，最高位 INCR 控制每读/写一字节后是否地址自增。NBYTES 只控制 STM32 的传输字节数，不会自动设置从机 MAP.INCR，这两个条件必须分别满足。

练习选从 0x01 开始读取三个连续寄存器：器件层组合 MAP=0x01|0x80=0x81，先用现有发送接口写入该指针，再用 I2C_MasterRead 接收三字节。沿用 CS42L51 手册的 STOP → START 流程，控制器函数不含音频芯片专用的 0x80。正常接收顺序是数据0后主机 ACK、数据1后 ACK、数据2后 NACK、STOP；在 NBYTES=3、AUTOEND=1 时由硬件处理，不逐次手动操作 ACK 位。第 46 页寄存器表给出复位默认：0x01 为 D9（修订号可变化）、0x02 为 00、0x03 为 AE；这些是手册默认值，非本轮新增实测。实现前先说明主机接收长度与器件寄存器自增的分工。

当前仅继续教学并维护记录、README，不修改驱动或应用逻辑、不新增构建和接收上板结论。中断、DMA 和音频播放仍按后续路线安排。

`inc/i2c.h` 声明、`src/i2c.c` 实现 I2C_MasterRead。参数检查在访问硬件前完成；等待 BUSY、接收及等待 STOP 共用 TIM2 起始 tick，0 tick 不发起 START。CR2 一次设置原始七位地址、读方向、NBYTES、AUTOEND=1、RELOAD=0，再发起 START。RXNE 到来后读取 RXDR 并更新 received；末字节与 STOP 同时到来时先取数据。STOP 时核对 NACK 和总接收数量，传输中超时请求 STOP，不等待恢复完成。缓冲区容量须由调用者保证，失败可能留下部分结果，不承诺回滚或总线恢复。

`user/main.c` 新增 cs42l51_verify_multibyte_read，先用已有寄存器接口读取 0x01～0x03 作为单字节参考，再发送 MAP=0x81，随后调用 I2C_MasterRead 接收三个字节。对照 single/burst 值逐项比较，全部一致才输出 PASS，不将 00/AE 等配置默认值写死为通过条件。I²C 访问失败即报告对应操作及错误原因，接收失败后不显示或比较可能只更新了一部分的数组。原 ID 核对、0x0C 写入与恢复验证保留，全部成功后才进入本次新增验证。新增接口和辅助函数均补齐功能、参数、返回值注释。

## 后续接口规划

学习者询问 I²C 还有哪些函数需要编写。核对当前 i2c.h/c 后，确认已有初始化、单字节收发、多字节收发及重复 START 的单字节寄存器读取。后续按能力补齐，不要求将每个寄存器操作都包装成公开函数，也不立即代写。

建议接口名和职责如下，均为待学习计划：

- I2C_MasterWriteRead：推广现有组合读取，在一次访问中先发送一组字节，再重复 START 接收一组字节；控制器层不解释 CS42L51 的 MAP.INCR。当前分离发送、接收已可操作本器件，此接口用于学习通用组合事务。
- CS42L51_ReadReg / CS42L51_WriteReg：新增器件层文件后封装固定地址、寄存器协议，应用层不再重复组织收发流程。
- CS42L51_UpdateBits：对适合读改写的配置寄存器只修改指定字段，保留其他字段；不推广到只读、写一清除或有读副作用的寄存器。
- 错误处理辅助函数：补现有循环对 BERR、ARLO 等硬件错误的检测，并按错误类型清理传输状态，可用内部 I2C_Abort 等函数集中处理。仲裁丢失后不能无条件请求 STOP；外设重置也不保证解除外部器件拉低 SDA 的情况。具体恢复接口及过程在学习手册规则后确定。

超过 255 字节的 RELOAD、从机模式、中断及 DMA 后续按需求安排；总线恢复须区分控制器状态与线路被拉低，不为凑函数数量提前扩展。下一次仍先理解已通过的多字节接收实现，再进入寄存器字段操作和器件层封装，之后补错误处理；组合接口结合重复 START 复习安排。本轮只核对代码和维护学习计划，无源码修改、构建或新增板端结论。
