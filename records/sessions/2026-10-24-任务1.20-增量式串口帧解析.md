# 任务 1.20：增量式串口帧解析

日期：2026-10-24。阶段 1，任务 1.20 开始。

## 学习目标

把任务 1.19 的固定帧格式应用到连续 UART 字节流中。接收函数每次可能只给出一部分数据，也可能一次给出多帧；解析器必须保存跨调用状态，识别完整帧、校验并恢复同步。

## 帧格式回顾

```text
SOF=0xAA | LEN=0..8 | CMD | PAYLOAD[LEN] | CHECKSUM
```

总长度为 `LEN + 4`。校验和为 LEN、CMD 和 payload 的 8 位累加和，不包括 SOF 和 CHECKSUM。

## 设计原则

- 接收缓冲区容量固定，不动态分配。
- 每次输入一段字节，按字节推进解析器状态。
- 帧不完整时保留已收到的数据，等待下一次输入。
- SOF 不匹配时丢弃当前候选字节，继续找 `0xAA`。
- LEN 大于 8 时拒绝该候选帧并重新同步。
- 完整帧校验失败时不产生有效帧，并继续寻找后续 SOF。
- 解析器一次可以输出多个完整帧；接口设计需明确输出容量不足时如何处理未消费数据。

## 当前教学入口

概念入口：若第一次输入只有 `AA 02 10`，解析器已收帧头、LEN=2 和 CMD=0x10，还缺 2 个 payload 字节及 checksum。下一次输入 `01 02 15 AA 00 20 20` 后应输出两帧：`AA 02 10 01 02 15` 和 `AA 00 20 20`。学习者理解需要保留第一次输入，但首答帧数为 1，已纠正为 2。

## 解析器 API（当前约定）

采用逐字节输入，避免接口一次要管理多个输出帧：

```c
typedef struct {
    uint8_t command;
    uint8_t payload_length;
    uint8_t payload[8];
} frame_t;

typedef struct {
    uint8_t bytes[12];
    size_t used;
    size_t expected;
} frame_parser_t;

void frame_parser_init(frame_parser_t *parser);
int frame_parser_push(frame_parser_t *parser, uint8_t byte, frame_t *frame_out);
```

`frame_parser_push` 每次处理一个字节：返回 0 表示当前还没有完整有效帧（含忽略帧外垃圾）；返回 1 表示刚输出一个完整有效帧；返回 -1 表示 parser/frame_out 参数为空；返回 -2 表示发现非法长度或校验失败并丢弃当前候选帧。解析失败后应能继续搜索后续帧。一个输入块中的所有字节由调用者循环传入，因此可连续产出多帧。

测试程序负责逐字节传入两帧拼接数据，并收集两次返回 1 的结果。状态和帧缓存为固定大小，不使用动态内存。

## 验收标准

学习者提交 `task20_parser.c` 首版。`frame_parser_init` 检查 NULL 并清零 used/expected/bytes，基本正确。`frame_parser_push` 尚未通过：非 SOF 字节在 used==0 时落入后续分支，可能访问尚未写入的 LEN；无条件 else 追加后立即 return 0，使后续校验代码不可达；checksum 调用把字节值当 data 指针、把 CMD 值当长度、把 frame_out 当 uint8_t 输出，参数类型均错误；校验比较也将 frame_out 指针与字节比较；缺少完整帧后状态复位及最终返回路径。下一步拆分状态分支后修改。

第二版 `push` 已忽略 used==0 时的非 SOF 字节，并在 LEN 字节处检查上限；但 SOF 被追加后 used==1，代码随即读取 `bytes[1]` 设置 expected，读取了尚未初始化的 LEN。应将 used==0 的帧头识别独立处理并返回；prior-used==1 时校验并存储 LEN，令 used=2 并设置 expected；之后才进入一般追加。checksum 参数仍错误，应传 `&parser->bytes[1]`、`(size_t)parser->bytes[1] + 2u`、`&checksum`。还需对校验失败重置并返回 -2，成功复制 frame_out 后重置并返回 1，补齐函数返回路径。源文件调用 checksum 时需包含 `task19_frame.h`。

第三版 `push` 已改正 checksum 参数。当前 LEN 阶段仍在保存当前 byte 之前读取 `parser->bytes[1]` 计算 expected，应先存 LEN 并递增 used，再据该 LEN 设置 expected。SOF 分支应存入后立即返回 0；完整帧校验成功时复制输出、重置并返回 1；校验失败时重置并返回 -2；未完成时返回 0。当前成功/失败后未清除状态，函数末尾有缺少返回路径。

第四版 `push` 已改为用 LEN 当前字节设置 expected，顺序正确；但 used==0 且 byte!=SOF 时把垃圾字节写入 bytes[0]，应完全忽略并返回 0。SOF 被追加后仍继续运行，expected 尚为 0，导致最终走到无返回路径；识别并缓存 SOF 后应立即返回 0。校验失败分支尚未 `frame_parser_init`，会污染后续解析；应重置并返回 -2。函数所有路径都需明确返回。

第五版 `push` 已单独处理 used==0，并完成成功帧输出及成功/校验失败时的状态重置。但帧外垃圾当前返回 -2，应按契约返回 0；SOF 缓存后没有设置 `used=1`，导致后续 LEN 字节仍被当作 SOF；函数末尾仍没有返回值。修正后继续复审。

补充参考设计：建议将 push 明确分成空闲找 SOF、等待 LEN、收集其余帧字节三阶段；预期总长只在 LEN 保存后设置，调用前需先 init parser。通用追加前保护 `used/expected` 不超出固定缓存。CHECKSUM 必须用局部 `uint8_t` 输出变量接收。校验成功复制 frame_out 后重置；坏 LEN/checksum 重置后返回 -2；帧外垃圾返回 0。增强重新同步时，可在错误字节本身等于 SOF 时把它保留为下一候选帧头，而不是丢掉。学习者询问改进方式，教师将提供参考实现示例，但不直接编辑学习者源文件。

学习者提交最终版 `frame_parser_push`：空闲时忽略非 SOF 字节；收到 SOF 后缓存并设置 used=1；LEN 超限时重置并返回 -2，合法时设置 expected；逐字节追加直至完整；使用 `frame_checksum(&bytes[1], LEN+2, &checksum)` 校验；成功时复制 command/length/payload、重置并返回 1；校验失败时重置并返回 -2；不完整时返回 0。源码审阅通过。`frame_parser_init` 同样通过。下一步编写解析器测试并严格编译运行。
