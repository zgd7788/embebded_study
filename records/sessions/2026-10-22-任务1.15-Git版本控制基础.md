# 任务 1.15：Git 版本控制基础

## 目标

理解 Git 如何记录项目变化，并能区分工作区、暂存区和提交记录；先学会安全检查当前仓库状态，再学习选择性暂存、查看差异和提交。Git 是阶段 1 的工程基础，不代表当前练习代码必须立即提交。

## 核心概念

- **工作区**：磁盘上当前可见的文件内容；修改文件首先改变这里。
- **暂存区**：下一次提交准备收录的内容清单。`git add` 会把所选路径当前内容放入暂存区，不等于提交。
- **提交（commit）**：把暂存区内容保存为一条有说明的本地历史记录；提交不是上传到远端。
- **版本历史**：先前提交构成的本地快照序列，可用于检查项目如何变化；远端同步是另一项操作。

## 当前练习：只读检查

在 `C:\Users\zgd\Desktop\study` 下打开 PowerShell。`git -C .\learning` 只让 Git 从 `learning` 子目录作为当前工作目录执行命令，不会自动把状态或差异范围限制在该目录。若要把 `status` 和 `diff` 限定在 `learning`，须在 `--` 后显式给出 `.` pathspec。当前已取得一轮只读结果，不要求重复执行：

```powershell
git -c safe.directory=C:/Users/zgd/Desktop/study -C .\learning status --short --branch -- .
git -c safe.directory=C:/Users/zgd/Desktop/study -C .\learning diff --stat -- .
git -c safe.directory=C:/Users/zgd/Desktop/study -C .\learning log -5 --oneline --decorate
```

- `-c safe.directory=...`：仅为本次 Git 调用提供仓库信任配置，不写入全局配置；路径应与 Git 报告的仓库根目录一致。
- `git -C .\learning`：让 Git 像从 `learning` 目录执行后续子命令；它只改变当前工作目录，不会缩小仓库状态范围。
- `-- .`：在 `status` 和 `diff` 中把路径范围显式限定为当前的 `learning` 子目录。`log` 查看提交历史，不检查工作区文件内容。
- `status --short --branch`：查看分支及该范围内工作区/暂存区的简短状态；`??` 表示未跟踪文件，`M` 表示修改。状态两列中左列是暂存区、右列是工作区，例如 ` M` 表示仅工作区修改、`M ` 表示已暂存、`MM` 表示暂存后又有新修改。此命令只读。
- `diff --stat`：概览该范围内尚未暂存的改动规模，不显示完整内容；只读。
- `log -5 --oneline --decorate`：查看所在 Git 仓库最近 5 条提交的一行摘要及分支/标签标记；只读。它读取提交元数据，不查看 `Project` 文件内容。

## 首次输出与解释

学习者提交了以下结果：

```text
## No commits yet on master
?? ../.gitignore
?? ../input/
?? ./
?? ../records/
```

`git diff --stat` 无输出；`git log -5 --oneline --decorate` 报 `fatal: your current branch 'master' does not have any commits yet`。

解释：仓库当前处于名为 `master` 的 unborn branch（尚无首个提交）。命令从 `learning` 子目录执行，但没有 pathspec，所以状态输出覆盖整个仓库；`../.gitignore`、`../input/`、`../records/` 和 `./` 是相对该子目录显示的未跟踪路径。`??` 表示路径尚未被 Git 跟踪，也没有进入暂存区；目录通常折叠显示为一行。没有显示已暂存条目。`git diff --stat` 默认比较工作区与暂存区，不会统计未跟踪路径，因此空输出不等于仓库没有文件或变化。`git log` 要显示提交历史；当前仓库没有任何提交，因此报错是预期结果，不代表损坏。
