# 2026-10-14 任务 0.6：主机与 ARM 二进制比较

## 当前阶段与目标

- 阶段 0：入门准备与基线。
- 本任务目标：亲自用原生 GCC 和 ARM 交叉编译器构建同一份最小 C 程序，并通过 ELF 文件信息确认二进制目标不同。

## 前置知识

- 主机原生 GCC 目标为 x86-64 Linux。
- 交叉编译器目标三元组为 `arm-linux-gnueabihf`。
- 搜索路径只是候选位置；要检查实际生成的程序架构，应查看产物本身。

## 学习者任务

1. 在 `learning/` 下新建一个练习目录和 `hello.c`，内容如下：

   ```c
   #include <stdio.h>

   int main(void)
   {
       puts("Hello, embedded!");
       return 0;
   }
   ```

2. 在该目录中分别执行以下构建与检查命令，保存实际输出：

   ```bash
   gcc hello.c -o hello-host
   arm-linux-gnueabihf-gcc hello.c -o hello-arm
   file hello-host hello-arm
   ```

3. 提交 `hello.c` 内容、三条命令的实际输出。
4. 用自己的话说明两个文件的目标架构有何不同。

本任务不要求运行 ARM 程序，不连接或操作开发板，也不安装或修改工具链。

## 验收标准

- [x] 提交源码和准确构建命令，确认同一份源码由两种编译器成功构建。
- [x] 提供 `file` 的实际输出。
- [x] 能根据产物信息区分 x86-64 与 ARM ELF。
- [x] 不把“能交叉编译”当作“已能在板端运行”；本次未报告 ARM 程序已运行。

## 学习者结果

hello-arm:  ELF 32-bit LSB pie executable, ARM, EABI5 version 1 (SYSV), dynamically linked, interpreter /lib/ld-linux-armhf.so.3, BuildID[sha1]=2c82f2db72a7c2e4581ad9cea7d97feb0c0d1f95, for GNU/Linux 3.2.0, not stripped

学习者解释：

> 主机是 x86-64 位架构的，使用交叉编译器执行后是 ARM 32 位架构的。
