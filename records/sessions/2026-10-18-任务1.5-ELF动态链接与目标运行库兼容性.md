# 阶段 1 任务 1.5：ELF 动态链接与目标运行库兼容性

## 任务目标

核对 reg_sim-arm 的动态加载器、共享库依赖和 GLIBC 符号版本，并与 FS-MP1A 板端实际运行库进行比较。任务完成前不运行、不烧录。

## 接口与验收契约

本任务不是函数实现任务，验收对象是“主机产物需求”和“目标板实际提供条件”的证据链。

必须确认：

1. ELF 使用的动态加载器路径；
2. ELF 的 NEEDED 共享库；
3. ELF 需要的 GLIBC 符号版本；
4. 板端是否存在同一路径的动态加载器；
5. 板端 libc 的架构和可见版本信息；
6. 能明确区分“架构匹配”和“运行库/符号版本兼容”。

## 操作顺序

先在 Ubuntu 主机检查 reg_sim-arm，再通过串口在 FS-MP1A 板端执行只读检查。遇到命令不存在或文件不存在，保留原始错误，不自行补推结论。

## 主机侧阶段结果（2026-10-18）

reg_sim-arm 的已提交输出显示：

- DT_NEEDED 包含 libc.so.6；
- DT_NEEDED 输出中还出现 ld-linux-armhf.so.3，需通过完整动态段进一步核实；
- 版本需求包含 GLIBC_2.4 和 GLIBC_2.34；
- PT_INTERP 为 /lib/ld-linux-armhf.so.3。

当前仍未据此判断板端兼容性。

完整 readelf -d 进一步确认：

- DT_NEEDED 为 libc.so.6 和 ld-linux-armhf.so.3；
- PT_INTERP 为 /lib/ld-linux-armhf.so.3；
- 未见 RPATH 或 RUNPATH；
- 动态段带有 NOW/PIE 标志。

这说明板端至少需要提供两个对应文件，并满足程序记录的 GLIBC_2.4 与 GLIBC_2.34 版本需求；板端实际情况待核对。

## 板端阶段结果（2026-10-18）

- uname -m：armv7l。
- /lib/ld-linux-armhf.so.3 存在，符号链接指向 ld-2.32.so。
- 一次 ls 命令将 libc 文件误写为 /lib/lib.c.so.6，不能作为 libc 不存在的证据；后续 strings /lib/libc.so.6 已成功读取正确路径，说明 libc 文件确实存在。
- 板端 strings 输出的 GLIBC 版本最高为 GLIBC_2.32。

当前结论：程序需要 GLIBC_2.34，而板端已观察到的最高版本为 GLIBC_2.32，存在明确的符号版本不兼容风险；在补充 libc 文件的 file/readelf 确认前，不运行程序。

## 最终验收（2026-10-18）

- /lib/libc.so.6 存在，指向 libc-2.32.so。
- 板端未安装 file 和 readelf，已保留原始命令错误，不将工具缺失误判为运行库缺失。
- 结合板端 armv7l、ARM hard-float 动态加载器路径、libc-2.32.so 和 strings 最高 GLIBC_2.32 的证据，确认板端运行库低于程序需要的 GLIBC_2.34。
