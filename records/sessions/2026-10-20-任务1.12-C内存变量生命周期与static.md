## 目标与边界

## 本轮补讲

- 作用域决定名字在源码的哪些位置可见；生命周期决定对象在运行时何时存在，两者不是同一概念。
- 此例普通局部对象具有自动存储期，常见实现使用栈；离开所在块后对象生命周期结束。
- 全局对象、文件作用域 static 对象和函数内 static 对象具有静态存储期，贯穿程序执行；函数内 static 的名字仍局限于其所在块。
- malloc 成功分配的对象具有分配存储期，持续到 free 释放；不会因局部指针离开函数自动释放。malloc 返回 NULL 表示分配失败，使用前须检查。
- 栈/堆是常见实现描述，不是 C 语言要求所有实现采用的固定内存布局；未初始化静态对象常见放 .bss，非零初始化可写静态对象常见放 .data，不能只凭所在物理段判断所有 C 语义。
- 局部指针 p 和它指向的动态对象不是同一对象；sizeof *p 在本例中获取 int 大小，不执行解引用。

## 局部教学示例（不创建或代跑练习程序）

```c
#include <stdlib.h>

int g_count;
static int g_limit = 10;

void demo(void)
{
    int local = 1;
    static int calls;
    int *p = malloc(sizeof *p);
    if (p == NULL)
        return;
    *p = local;
    ++calls;
    free(p);
}
```

本轮只讨论存储期和可访问性，不要求现在复制运行，也不把示例中的未使用 g_limit 当作 -Werror 编译练习。

学习者原话：

教师判断：

- g_count、g_limit、calls 具有静态存储期，贯穿程序执行，回答正确。用户的 call 按示例 calls 理解。
- local 在本例 demo 的函数块退出时结束生命周期，基本正确；“在函数内有效”仍须区分名字作用域与对象生命周期，不直接标为已完全掌握。
- free(p) 后不可继续访问 *p，正确；calls 再次调用时不会重置为 0，正确。示例成功分配路径中 calls 每次加一，若分配失败则提前返回不加一。
- “p 和 malloc 对象在 free 前都有效”不足以说明两者何时结束；需明确 free(p) 结束被分配对象的生命周期，并不结束 p 自身的生命周期。p 是普通局部指针对象，退出 demo 函数块才结束生命周期。

### 教师补讲与复习要点

| 对象 | 在本例何时结束生命周期 |
| --- | --- |
| g_count、g_limit、calls | 程序执行结束 |
| local、p 自身 | demo 函数块退出 |
| malloc 成功分配的对象 | 对应 free 调用释放时 |

- 对象仍存在不等于其中的旧指针值可安全使用。free 后 p 仍是存在的局部对象，但原指针值不再代表可访问的动态对象，不可解引用或再次 free。严谨的 C11 规则将指向已结束生命周期对象的指针值规定为不确定值，不教授“释放后安全打印/比较旧地址”。
- free 不会自动把调用者的 p 设成 NULL；可以直接 p = NULL，给仍存在的指针对象赋新值，这不读取旧指针值。但置空不恢复已释放内存，也不会自动修正其他别名。
- calls 是函数内 static，生命周期贯穿程序执行，但名字作用域仍在函数块内；不因离开作用域就销毁。
- 严格措辞校正：本例非 VLA 自动对象的生命周期对应关联块的执行，初始化在执行到声明时进行，不把此前简化的“执行到声明才创建”作为 C11 严格定义。
- 技术依据：WG14 C11 草案 N1570，6.2.4、7.22.3、7.22.3.3；官方文档 https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf 。

### 所有权与返回指针补讲

内存所有权指约定谁负责最终释放一块动态内存，并非 C 编译器自动管理。分配函数可以返回动态对象的地址，让调用者保存这个地址并负责 free。局部指针本身结束生命周期，不会使所指动态对象自动失效；返回的是地址值，不是返回局部指针变量本身的地址。

不能用返回普通局部 int 变量的地址替代动态分配，因为那个 int 在函数返回时生命周期结束；也不能返回已 free 的地址。

### 已通过的实现练习：int_create

```c
int *int_create(int value);
```

完整函数契约：

- 功能：动态创建一个 int 对象并初始化为 value，返回后对象仍可供调用者使用。
- 参数 value：任意 int 值；无需额外业务范围校验。
- 成功：返回新分配 int 对象的有效指针，*返回指针等于 value；尚未释放的多次成功调用应各自拥有独立对象。
- 失败：malloc 分配失败时返回 NULL，不能解引用 NULL，不打印错误。
- 头文件：使用 <stdlib.h> 提供 malloc/free/NULL 的声明或定义。
- 所有权：成功后由调用者保存返回指针，使用完负责 free 恰好一次；函数不能在返回前释放成功返回的对象。
- 禁止返回普通局部变量地址、静态/全局对象地址或已释放地址；静态对象不符合“新动态对象”契约。
- 验收：分配尺寸匹配 int，分配失败先处理，正确初始化，返回地址在函数结束后仍有效，释放责任清楚。教师只审阅学习者提交的函数，不代写实现、不代编译运行。函数通过后按约定不收集逐项测试证据。

### static：存储期与链接属性补讲

- 函数内 static 局部对象有静态存储期，可跨调用保留值；名字作用域仍限于所在块，没有链接。
- 文件作用域变量本来就具有静态存储期，即使没有写 static 也贯穿程序执行；此处加 static 的主要区别是把该名字的链接属性设为内部链接。
- 内部链接：同一翻译单元内的声明可指代该对象；其他独立翻译单元不会仅通过同名声明引用到这个内部对象。初学阶段可按各 .c 文件分别编译来理解，严格的翻译单元包含预处理展开后的头文件。
- 这不是内存访问安全隔离，其他代码仍可能通过显式传出的指针间接访问；也不代表 static 变量位于栈中。
- 文件作用域 static 函数同样限制函数名的链接属性，不用变量生命周期术语解释函数。
- 依据：WG14 C11 草案 N1570，6.2.1、6.2.2、6.2.4。

### static 跨文件回答与措辞纠正（2026-10-20）

学习者原话：

> 不是同一个对象，不会跟着改变，他们的作用域只是自己所在的文件

教师判断：两个对象独立、修改不互相影响的结论正确，判断通过。作用域的表述不全错，但不能以此代替链接属性解释对象是否相同：两个名字都在各自文件的声明位置之后具有文件作用域；counter.c 的 static count 具有内部链接，main.c 的 int count = 100 具有外部链接。二者不是同一对象的关键是内部链接对象不会与另一翻译单元的外部链接对象合为一个。

补讲局部示范：

```c
/* main.c */
int count = 100;

/* other.c：独立编译，不 include 上面的 .c */
extern int count;
```

此处 other.c 的匹配声明引用 main.c 的同一个外部链接对象，不是在 other.c 新建对象；它不会引用 counter.c 的 static count。extern 声明用于说明已有外部对象，此例不带初始化，不把所有 extern 声明一概说成永远不是定义。这里不是内存安全隔离，文件内代码仍可显式传出 static 对象指针。

复习三概念：作用域回答源码何处可用名字；生命周期回答对象何时存在；链接属性回答不同声明是否指同一对象。此为教师补讲，不伪称已收到学习者新的完整复述。依据 WG14 C11 N1570 6.2.1、6.2.2、6.2.4。

### 最后反例回答与易错点（2026-10-20）

学习者原话：

> bad_a执行结束后，local生命周期就结束了，地址自然不存在，bad_b函数中free p后，p的生命周期就结束了

教师判断：

- bad_a 正确指出函数返回时 local 生命周期结束。但“地址自然不存在”不准确：不能把对象生命周期结束等同于数字地址被抹除或立刻取消内存映射；即便内存残留旧数据，也没有有效 local 对象可以经返回指针访问。
- bad_b 的解释未通过：free(p) 结束 malloc 分配的 int 对象的生命周期，不是局部指针对象 p 的生命周期。p 自身一直存在到 bad_b 退出函数块。
- 存在两个对象：局部指针 p（用于存放地址值），以及动态分配的 int（存放 value）。释放后前者仍存在，后者已失效；不能再使用旧指针值返回可访问对象、解引用或重复释放。严格 C11 规则下指向失效对象的指针值成为不确定值，不演示安全打印该旧值。
- free(p) 后可以直接给仍存在的变量 p 赋值，例如 p = NULL；这不读取旧值，也不能恢复原动态对象。不新增对应运行实验。
- 对比顺序：bad_b 中动态 int 在 free 时结束；指针变量 p 在函数块退出时结束。bad_a 中 local 在函数块退出时结束，两例都不能给调用者提供仍有效的新动态 int 对象。
- 技术核对：WG14 N1570 6.2.4（存储期与对象生命周期）、7.22.3.3（free），以及 WG14 DR260 对失效对象指针值的说明。
