# 阶段4 I²C 主机单字节接收

前置状态：2026-11-22 学习者确认 CS42L51 单字节发送例程上板通过。2026-11-23 已更新 261122 工程说明，本轮进入接收函数设计，由学习者实现。

建议接口 `int I2C_MasterReadByte(i2c_t *I2Cx, uint8_t addr7, uint8_t *data_out, uint32_t timeout_ticks)`。返回值报告状态，输出指针用于交付数据；调用时仍传 `0x4A`。当前头文件的方向宏拼为 `WD_WRN`，手册名称为 `RD_WRN`，bit 10。

沿用发送函数的参数检查、BUSY 等待、ICR 清旧标志与整笔事务共用的超时预算。接收改为 RD_WRN=1、NBYTES=1、AUTOEND=1、RELOAD=0、ADD10=0，在 START 前完成设置。检测到 ISR.RXNE（bit 2）后读取 RXDR 并保存到局部变量，记录已接收状态；确认正常 STOP 后再写入 data_out。若 RXNE 与 STOPF 同时出现，先读取数据再判断结束，防止漏掉最后一个字节。

主机正常接收末字节时自动发送 NACK 和 STOP，这个主动发出的 NACK 不会置位表示“收到 NACK”的 NACKF。地址未被从机应答则仍按 NACKF 错误处理。返回值沿用 0 成功、-1 参数错误、-2 超时、-3 收到 NACK，-4 用于结束但未取到数据。实现及板端验证尚未完成。下一步审阅函数，再接入写寄存器指针后的读取事务与 UART4 芯片 ID 显示。

接收函数首审。RD_WRN 名称已修正，声明与定义一致，配置读方向、单字节和自动 STOP，沿用同一超时起点。当前循环先检查 STOPF，若 RXNE 与 STOPF 同时出现，会在读取 RXDR 前返回 -4，需要先处理接收数据。当前 RXDR 直接写入 data_out，后续 STOP 等待超时或出错时输出也已改变，需要用局部变量暂存，仅在正常完成后交付。建议将接收标志命名为 data_received。Cortex-A7 编译检查确认 NULL 未声明，应在 i2c.c 包含 stddef.h。当前主程序仍只执行发送，接收尚未上板验证。

接收函数复查。已补 stddef.h，先读 RXDR 到局部变量，再判断 STOP，Cortex-A7 编译检查通过。接收标志仍在循环末尾才置位，因此同时出现 RXNE 和 STOPF 时，STOP 分支会误判未接收。应在读取 RXDR 的同一分支立即设置 data_received，输出指针只在 STOP 正常完成、准备返回 0 时赋值，删除末尾重复接收判断。当前仅源码与编译检查，未接入板端读取。

接收函数再次复查通过。RXNE 到来时先读取局部 data 并立即标记接收完成，STOP 分支先排除 NACK 和未收到数据，再写输出指针，重复判断已移除。当前 Cortex-A7 编译检查通过，接收尚未接入 main 或上板。学习者随后要求解释收发函数的 for 循环。围绕每轮读取一次 ISR、软件记录数据是否已提交或已取出、硬件自动发送 NACK/STOP、成功和超时的退出路径逐项讲解，并以正常发送、正常接收及 RXNE/STOPF 同时出现说明执行顺序。讲解未直接视为学习者已掌握。

学习者确认理解上述循环讲解。进入应用集成：在写入寄存器索引成功之后发起单字节接收，地址仍为 `0x4A`，通过输出指针获得 ID。读失败时报告错误并结束本次操作；成功后用 UART4 显示十六进制 ID，再核对芯片标识与修订号。由学习者修改应用，接入和上板结果仍待确认。

学习者询问用于输出 ID 的发送接口。核对现有 console_write 只接受字符串，不能像 printf 一样传格式参数；现有 UART4 字符与字符串发送接口可复用。讲解用十六进制字符表将 ID 高低四位转换为两个字符，再填入字符串交给 console_write。应用集成初稿在写成功分支调用读取后立即 return，导致读取结果处理不可达；写失败路径则可能使用未赋值的 read_result。指导调整为写成功退出第一个 switch、写失败直接 return，再统一调用读函数并处理结果。应用仍待学习者修改与验证。

应用集成复查。十六进制字符表和字符串填充正确。写成功分支虽然已移除 return，但未加入 break，执行完读取会贯穿到参数错误分支；Cortex-A7 编译检查因 implicit-fallthrough 触发 Werror。写失败分支仍用 break，之后会使用未赋值的 read_result。指导第一个 switch 的成功分支只保留 break，错误分支打印后 return 1，再将读取调用统一移到第一个 switch 后。待学习者修正，未上板读取 ID。

应用集成终审。学习者已修正写结果的 switch：成功 break，所有失败路径 return 1；随后定义并赋值 const int read_result，再判断读取结果。读取成功才使用 id，message[5]/[6] 分别填入高低四位对应的十六进制字符，失败路径最终返回 1。I2C_READ_TIMEOUT_TICKS 已提为宏。执行 make -B，所有 Cortex-A7 源文件在 -Wall -Wextra -Werror 下编译、链接通过，并生成 build/tim2.bin 和反汇编。未修改学习者源码。提示字符串 readd 的拼写和旧写入说明注释不影响本次功能；后续整理时修正。下一步由学习者上板并提供 ID=0xXX，检查 (id & 0xF8U) == 0xD8U，低三位为修订号；当前没有板端读取结果。

板端反馈与本项结论。学习者报告“最后得到ID=D9”，按应用的十六进制输出解释为 0xD9，即二进制 11011 001。高五位 11011 符合 CS42L51 固定芯片标识，低三位 001 表示修订号字段值为 1；等价检查为 (0xD9 & 0xF8) == 0xD8、(0xD9 & 0x07) == 1。结合已通过的源码审阅和完整交叉构建，当前以 STOP 分隔的寄存器索引写入与单字节读取例程功能通过。上板结果依据学习者报告，无额外波形、SCL 频率、故障注入或重复性测量证据，不据此宣称所有错误路径或时序已验证。本轮仅更新记录，不修改驱动、不重复构建。后续从重复 START 的寄存器读取继续，再学习多字节收发和错误恢复；中断与 DMA 保持后置。

## 重复 START 参考函数（学习者明确授权代写）

学习者询问“连接成一次连续事务”的含义，已对比两次独立 START/STOP 与写寄存器地址后重复 START 的流程。随后学习者将 Makefile 的 TARGET 改为 i2c5_cs42l51，并明确要求教师完成寄存器读取函数供其学习。本次授权限于当前 I²C 参考实现，不改变风扇、马达独立设计和编码约束，不把教师代写当作学习者独立实现通过。

新增 `I2C_ReadRegisterByte(i2c_t *I2Cx, uint8_t addr7, uint8_t reg, uint8_t *data_out, uint32_t timeout_ticks)`，并在头文件补声明与 ISR.TC（bit 6）宏。函数按当前单主机、轮询方式使用，支持 I2C5、7 位从机地址、一个字节的寄存器地址与一个字节的数据。先等待 BUSY 清零，写段配置 AUTOEND=0、RELOAD=0、NBYTES=1，TXIS 后提交寄存器地址，TC 后配置读方向、AUTOEND=1 并设置 START；不在两段之间等待 BUSY 清零。读段先处理 RXNE，再判断 STOP/NACK，成功才写输出值。全程共用一个起始 tick，0 tick 预算不发起事务。已开始传输后的超时请求 STOP，但不额外等待 STOP 完成，不实现总线恢复或仲裁丢失/总线错误的专用处理；调用前提和失败副作用均写入功能、参数、返回值注释。

硬件依据核对：RM0436 Rev 2 第 52.4.9 节第 2556 页说明 AUTOEND=0 时完成 NBYTES 后置 TC、拉低 SCL，软件设置 START 可产生重复 START 并清 TC；收到 NACK 时硬件仍会自动发 STOP。CR2 的 START/AUTOEND 与 ISR.TC 定义在第 2587～2589、2595 页。CS42L51 DS679F1 第 44 页图 25 和伪代码明确使用 MAP 写入后的 STOP，再 START 读取；第 22 页虽列重复 START 的时序参数，仍不能仅据此认定寄存器前导写可以省略 STOP。因此纠正此前直接建议以组合读取替换当前芯片读法的过度推断。当前 main 保留已按手册验证出 D9 的 STOP → START 流程，重复 START 函数暂供学习，器件兼容性与板端波形仍待验证。

验证：执行 make -B，Cortex-A7 全量编译、链接及 i2c5_cs42l51.bin/dis 生成通过。主机辅助程序 `tmp/i2c_repeated_start_review.c` 以普通 RAM 映射 I2C5 地址，在时间源读取处驱动选定硬件事件，直接调用实际 i2c.c；582 项检查通过、0 失败。覆盖参数错误不改寄存器/输出、零预算、正常读取及 0/255 数据、RXNE 与 STOP 同时出现、写地址/寄存器/读地址 NACK、NACK 与 TC 同时出现时不进入读段、两段意外 STOP、BUSY/TXIS/TC/RXNE/STOP 等待超时、整笔事务共用预算、计时回绕和超时 STOP 请求。该模拟不验证电气时序、真实 W1C 副作用或 CS42L51 对新流程的兼容性，无新增板端结果。

## 晚间代写授权、写入验证与明日复习

新增 I2C_MasterWrite：头文件补 stddef.h、size_t 参数声明；实例、7 位地址、非空缓冲区和 1～255 长度先校验，零预算不发起事务。发送前一次配置 CR2，NBYTES 等于长度，RELOAD=0、AUTOEND=1。每次 TXIS 且未收到 NACK 时提交 data[sent]，用 size_t 计数；发送结束继续等 STOP，只有未收到 NACK 且 sent==length 才返回 0。参数错误 -1，超时 -2，NACK 后 STOP 为 -3，提交不足的 STOP 为 -4。整个操作共用起始 tick，已开始传输后的超时会请求 STOP，但不等待恢复完成；失败前可能已改变从机状态，注释明确这一副作用。

寄存器依据：查阅 CS42L51 DS679F1 第 49 页读写属性和第 60 页第 6.11 节，选择 0x0C ADCA Attenuator，其八位均为衰减控制，无保留位；FF 表示 -1 dB、FE 表示 -2 dB。main 在读到且确认 ID 高五位为 11011 后，先读取原值，正常情况选 FF，原值已经 FF 时改选 FE。通过 {0x0C, test_value} 两个字节做一次 NBYTES=2 的写入，再用已上板的重复 START 单字节读取接口读回比较。MAP.INCR=0，只改一个寄存器，不写只读 ID、供电或音频接口寄存器。本例不开展音频流功能。

原值恢复：只要尝试过测试值写入，不论该写入返回失败、测试读回失败或比较不一致，都继续尝试写回保存的原值，然后读回核对。恢复失败明确输出操作名和错误原因；恢复读回不一致输出 restore FAIL。恢复成功不掩盖前面的测试失败，只有测试读回和恢复全部成功才输出 I2C multi-byte write PASS。ID 不匹配或原值读取失败时不尝试测试写入。
