# 2026-10-14 任务 0.1e：Linux 程序启动诊断顺序

## 任务目标

把程序无法启动时的基础诊断层次串起来。

## 已学诊断链

```text
1. 目标架构与二进制格式
2. ELF 动态加载器
3. 共享库依赖及其架构/ABI
4. 当前用户的执行权限
```

不同现象对应的优先方向不同：

- `Exec format error`：优先查架构和格式。
- 文件存在但 `No such file or directory`：查动态加载器，再查共享库。
- `Permission denied`：查执行权限和相关目录权限。
- 整板不启动或外设时序异常：才进入复位、时钟、供电和硬件初始化诊断。

## 当前检查题

学习者回答：C 程序编译成为可执行文件后，会先加载 ELF 文件，然后调用 ELF 动态加载器，加载 `.so` 文件完成动态链接，然后执行程序代码。程序无法启动时，先看架构是否是 ARM，再看是否存在动态加载器、是否有共享库、有没有执行权限。

评价：顺序和关键概念正确，任务通过。补充精确点：Linux 内核识别 ELF 后，根据 ELF 头中的解释器路径启动动态加载器；静态链接程序不需要动态加载器或外部共享库。目标程序除了 ARM 架构，还必须匹配目标位数、ABI/浮点调用约定及系统库版本。
