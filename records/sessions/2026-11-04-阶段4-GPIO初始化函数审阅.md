## 初始化函数问题

1. **输出模式未设置。** `GPIO_OUPUT_MODE` 分支配置 OSPEEDR、OTYPER 和初始 BSRR 电平后，没有更新 MODER 的目标两位为输出 `01`。因此引脚未必成为 GPIO 输出。建议先清 `MODER[2*index+1:2*index]`，再写入输出模式值。
2. **OTYPER bit 位置错误。** 当前先清 `1U << index`，随后执行 `OTYPER |= GPIO_Init->Otype`。`GPIO_OUTPUT_OD` 值为 1，却没有左移到当前 `index`，因此配置 pin 5 开漏会置 OTYPER bit 0；推挽值 0 则因前面的清位碰巧正确。应按类型显式清目标 bit，再按 Otype 设置 `1U << index`。
3. **GPIO 时钟使能未执行。** Init 没有写 RCC_MP_AHB5ENSETR，尽管头文件定义了该寄存器；若函数负责初始化硬件，应为 GPIOZ/AHB5 设置 GPIOZEN bit0。若设计上时钟由调用者开启，须把它列为接口前置条件。当前函数还接受任意 gpio_t*，而 RCC 宏只对应 GPIOZ，需明确此 API 是 GPIOZ 专用还是支持多端口。
4. **参数/枚举未校验。** Mode、Otype、Speed、pupd、State 可被非法强制转换值传入。非法 Mode 目前 default 静默 break；非法 State 在输出分支会被当作 SET；非法配置值可写入相邻寄存器字段。应在任何寄存器修改前验证配置值，失败时避免半完成配置。
5. **PUPDR 配置不一致。** Input 分支清字段后设置 pull；Output 分支不设置 pull，Analog 分支也不定义 pull。若配置结构包含 `pupd`，需明确它对哪些模式生效，或在所有适用分支配置/明确保持当前值。
6. **AF 分支为空。** 传入 `GPIO_AF_MODE` 时函数不配置 MODER 或 AFSEL，调用者容易误以为初始化成功。要么明确本版本不支持并返回错误，要么加入 AF 字段及相应寄存器设置。
7. **错误反馈缺失。** 函数返回 void；NULL、空 Pin 及非法配置都静默 return，调用者无法判断失败。建议约定返回状态码。`Pin` 采用多位 mask 并逐脚配置可行；零 mask 应作为参数错误反馈。
8. **初始输出顺序。** 先用 BSRR 预装输出 latch 再把 MODER 切到输出，可避免切换模式时短暂输出旧值；但需要先确认时钟已开启。当前代码的初始电平在输出分支中先于 MODER（这一点顺序方向正确，只是最后没有实际切换 MODER）。

## 与三个操作函数的关联

- `HAL_GPIO_Write`、`Read`、`Toggle` 的模式前置条件目前未建立。Init 修正后应保证所选 pin 按请求模式完成配置，并在头文件契约中说明调用限制。
- Write 仍以 `_val > GPIO_PIN_SET` 判断非法状态，负枚举值可通过检查；应只接受 RESET/SET。
- Read 的失败返回值和有效低电平无法区分按学习者要求暂不作为本轮问题。
- BSRR toggle 可避免直接对 ODR 写，写高半区执行 reset、低半区执行 set；当前 toggle 分支方向正确。

## 复查（2026-11-04；用户明确时钟外部开启、AF 暂缓）

用户说明时钟由调用者负责开启，AF 功能暂时保留。本轮不把 Init 不写 RCC 或暂不配置 AFSEL 单独判为缺陷；调用者开启时钟应作为 Init 前置条件记录，且 AF 暂不对外承诺支持。

当前版本再次严格语法检查：`gcc -std=c11 -Wall -Wextra -Werror -fsyntax-only -I project/stage_3/261102/inc project/stage_3/261102/src/gpio.c` 退出码 0、无输出。但源码仍有关键行为问题：

1. **MODER 赋值在 switch 内、首个 case 标签之前。** C 的 switch 直接跳到匹配的 case 标签，因此执行不会经过 case 标签前两条语句。现在所有分支都没有实际更新 MODER。将公共 MODER 字段更新移到 switch 外；对暂未支持的 AF 分支不要先改 MODER 再空操作。
2. **enum 范围检查把合法最大值当非法。** 目前 `State >= 1U` 拒绝 GPIO_PIN_SET；`Otype >= 1U` 拒绝 GPIO_OUTPUT_OD；`pupd >= 2U` 拒绝 GPIO_PULLDOWN；`Speed >= 3U` 拒绝 GPIO_VERY_HIGH_SPEED；Mode `>= 3U` 拒绝 GPIO_ANALOG_MODE。应改为 `>` 对应最大枚举值，或逐合法枚举值白名单校验；同时确保负/任意 cast 值被拒。
3. **OTYPER 目标位仍错。** `GPIOx->OTYPER |= GPIO_Init->Otype` 没有把 OD=1 放到正在配置的 pin `index` 位。先清目标位后，应在选择 OD 时写入 `1U << index`；PP 时保持清零。
4. AF 功能暂缓：当前 `Mode >= 3U` 只拒绝 analog，AF=2 会进入一个空 case。若暂不支持 AF，应明确拒绝/无副作用返回，避免调用者误认为初始化成功。用户说“复用功能先保留”按暂缓实现理解；本轮不要求写 AFSEL。
5. `gpioinit_t` 含 `pupd`，但 Output 分支未应用该字段。定义它是否仅对 input 生效；若输出也允许设置内部偏置，则需要按 PUPDR 双位字段配置。
6. Init 返回 `void`，非法参数只静默 return；建议后续改成状态码，让调用者能发现失败，不阻塞本轮对核心位域修正。

已遵循本轮约束：时钟使能由调用者负责，不列为 Init 缺陷；AFSEL 暂不实现。仍未运行行为测试或上板。
