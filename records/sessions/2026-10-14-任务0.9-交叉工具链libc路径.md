# 2026-10-14 任务 0.9：查询交叉工具链的 libc 路径

## 当前阶段与目标

- 阶段 0：入门准备与基线。
- 本任务目标：让交叉编译器报告它能定位的 `libc.so.6`，区分开发主机工具链提供的目标库和开发板当前安装的运行库。

## 前置知识

- `hello-arm` 依赖 `libc.so.6`，并涉及 `GLIBC_2.4` 和 `GLIBC_2.34` 符号版本。
- 交叉工具链的目标库不等于开发板文件系统中的运行库。

## 学习者任务

在 Ubuntu 终端执行以下只读命令，把输出原样发回：

```bash
arm-linux-gnueabihf-gcc -print-file-name=libc.so.6
```

不要安装软件、修改配置、运行 ARM 程序或操作开发板。

## 验收标准

- [x] 提供命令的实际输出。
- [x] 能区分 Ubuntu 编译环境路径与 FS-MP1A 板端路径。
- [x] 不把该路径当作开发板上实际存在或兼容的证明。
- [x] 能说明该输出仍提供工具链侧信息：GCC 报告的 `libc.so.6` 路径及其 ARM 目标目录线索。

## 学习者结果

学习者提交的输出：

```text
/usr/lib/gcc-cross/arm-linux-gnueabihf/15/../../../../arm-linux-gnueabihf/lib/libc.so.6
```

学习者解释：

> 这是Ubuntu 编译环境，我都没有链接开发板，现在和开发板没有一点关系，什么也证明不了

学习者补充说明：

> 系统中交叉编译工具链相关文件的目录，目标为 32 位 ARM Linux，通常采用硬浮点 ABI

理解正确：命令报告 Ubuntu 编译环境中交叉工具链可见的库路径，目录名提供 ARM hard-float 目标线索；这不证明板端有同一文件或兼容运行环境。

## 得分与决定

通过，100/100。理由：能说明路径属于交叉工具链目标库目录，识别 ARM hard-float 目标线索，并与板端运行环境区分。
