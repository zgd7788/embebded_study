# 任务 1.4：交叉编译与 ELF 验证

## 任务目标

在 Ubuntu x86-64 主机上使用 arm-linux-gnueabihf-gcc 生成 ARM 32 位 Linux 程序，并使用编译退出状态、file 和 readelf 验证生成文件。

## 学习者理解

- 主机原生 GCC 通常生成 x86-64 Linux 程序。
- arm-linux-gnueabihf-gcc 运行在 x86-64 主机上，但生成 ARM 32 位 hard-float Linux 程序。
- file 用于快速识别 ELF 文件格式和目标架构。
- readelf 用于解析 ELF 文件结构。
- 架构匹配不等于目标板运行库兼容，也不等于板端实际运行成功。

## 已提交证据（2026-10-18）

目标文件：reg_sim-arm

readelf -h 显示：

- ELF32；
- little endian；
- ARM；
- Version5 EABI；
- hard-float ABI；
- PIE/DYN 类型。

readelf -l 显示动态加载器：

- /lib/ld-linux-armhf.so.3

学习者报告 echo $? 为 0；该结果只有在紧邻交叉编译命令执行时，才能证明编译命令成功。

## 最终验收（2026-10-18）

学习者提交了实际交叉编译命令：

arm-linux-gnueabihf-gcc -std=c11 -Wall -Wextra -Werror main.c reg_sim.c -o reg_sim-arm

紧邻命令的退出状态为 0。file 输出确认：

- ELF 32-bit；
- ARM；
- EABI5；
- PIE；
- 动态链接；
- 动态加载器为 /lib/ld-linux-armhf.so.3。

readelf 输出进一步确认 little endian、hard-float ABI 及相同动态加载器。

任务 1.4 通过，评分 100/100。

结论边界：已证明交叉编译产物的格式和目标架构正确；尚未证明 FS-MP1A 板端运行库兼容，也尚未在板端运行。
