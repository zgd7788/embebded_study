## 学习者反馈与本轮入口

学习者补充确认 UART4_TX 对应 PG11、UART4_RX 对应 PB2，并确认这组引脚就是当前 SecureCRT 使用的通道。无需重复做硬件接口识图。后续从 GPIO 复用登记入手：`gpio_t` 需要按硬件偏移扩展 AFRL/AFRH；LCKR 位于 BSRR 和 AFRL 之间，结构体映射中须保留该成员，否则 AF 寄存器偏移不正确。AF 配置结构需要保存每个引脚所需的 AF 编号，例如 PG11 使用 AF6、PB2 使用 AF8。接下来由学习者先自行修改结构体并提交代码，再讲解 AF 寄存器位域如何对应 pin index。

学习者随后提交结构体定义。`gpio_t` 的 MODER→OTYPER→OSPEEDR→PUPDR→IDR→ODR→BSRR→LCKR→AFRL→AFRH 顺序正确；`gpioinit_t` 的 `AlternateFunc` 字段能承载 0–15 的 AF 编号，但需在初始化函数中验证范围。建议寄存器映射成员用 `uint32_t`，明确每个 MMIO 寄存器宽度（`gpio.h` 已含 `<stdint.h>`）。

AF 位域计算讲解：每个 pin 在 AFR 中占 4 位。引脚号 0–7 选择 AFRL，8–15 选择 AFRH；该寄存器内的偏移均为 `(pin_index % 8) * 4`。因此 PG11→AF6 写 AFRH 的 shift=12 字段；PB2→AF8 写 AFRL 的 shift=8 字段。GPIO 的 MODER 对应 pin 字段还需设置为 alternate-function mode（`GPIO_AF_MODE` 的编码 2）。依据 ST RM0436 的 GPIO register map，AFRL/AFRH 偏移分别为 0x20/0x24，LCKR 为 0x1C。下一步由学习者自行实现 HAL_GPIO_Init 的 AF 分支，再检查掩码、字段清除和寄存器映射；本轮无编译、上板结果。

## GPIO_AF_MODE 分支首轮审阅

学习者提交 AF 分支；只读检查当前 gpio.c 的外层循环确认 index 为引脚编号、_pin 为 1U << index、GPIO_Init->Pin 为所选引脚掩码，原 shift 为 MODER 使用的 index*2。入口已加入 AlternateFunc >15 的检查，Pupd 名称也已同步。

当前分支尚未通过：

- 不能用 GPIO_Init->Pin <8 选择 AFRL/AFRH，也不能用 _pin*4 计算偏移。PB2 的 index=2、_pin=4；PG11 的 index=11、_pin=2048。应使用 index<8 选择寄存器，用独立的 af_shift=(index%8)*4 计算位移，保留原 shift 给 MODER 使用。
- 清除字段应取反整个移位后的掩码：~(0xFU << af_shift)。现代码对位移量取反，会产生远大于寄存器宽度的移位，属于未定义行为。AFRH 同样每字段占4位，应使用15（0xF），不能用16（0x10）。
- AlternateFunc 是 uint8_t，左移前先转 uint32_t，避免整数提升为 int 后在高位字段发生有符号溢出。
- MODER 应写 GPIO_AF_MODE（编码2），当前写 GPIO_OUTPUT_MODE 会进入普通输出模式。
- AF 分支还应按配置设置 OTYPER、OSPEEDR、PUPDR；这部分电气配置不会由 AFR 或 MODER 自动完成。

本轮只给出变量区别、通用位域操作示例和修正要求，由学习者自行修改分支；未代改源码、编译或执行板端程序。

## GPIO_AF_MODE 分支第二轮审阅

学习者已把寄存器选择改成 index<8，补齐 OTYPER、OSPEEDR、PUPDR，并正确写 GPIO_AF_MODE；以上改动方向正确。只读检查 gpio.c 确认 af_shift 的定义仍是 index*4，不能直接认为已经采用上一轮建议的寄存器内偏移。

剩余问题：AFRH 清位使用 af_shift-0x10（16），但8个引脚各占4位，若从 index*4 换算高半区位移应减32（0x20）。例如 PG11 全局位移44，目标位移12，减16得到28会清错字段。统一方案是把上游 af_shift 改成 ((uint32_t)index%8U)*4U，让 AFRL/AFRH 均直接用它；AFRH 设位还残留 _pin-8 的掩码运算，必须改为同一个 af_shift。两个寄存器的 AlternateFunc 都应先转 uint32_t 再左移，支持合法 AF 编号写入最高4位字段。

本轮提供局部 AFRH 清位/设位示例及 PG11 数值对照，由学习者自行修改，未代改源码、编译或执行板端程序。

## UART GPIO 初始化源码复查

学习者报告 GPIO 初始化已完成。只读检查 `gpio.h`、`gpio.c`、`user/main.c`：AF 分支现已使用 `index<8` 选择 AFRL/H、`(index%8)*4` 作为 AF 字段位移，配置 OTYPER、OSPEEDR、PUPDR，并将 MODER 设为 GPIO_AF_MODE。main 中 PG11 使用 AF6、PB2 使用 AF8；时钟位选择 GPIOB bit1、GPIOG bit6。

发现一个关键基地址错误：当前 `GPIOG` 宏仍为 `0x50002000`，该地址是 GPIOA；RM0436 存储器映射中 GPIOG 基地址为 `0x50008000`。应由学习者自行修正此地址，否则 TX 初始化会访问错误端口。引用 ST RM0436 地址映射。

另外，`AlternateFunc` 左移前仍需转换为 `uint32_t`，避免例如 AF8 写入 AFRL 高位字段时出现有符号 int 溢出；推荐寄存器结构体成员统一采用 `uint32_t` 表示 32 位寄存器。当前 RX 上拉和 TX 配置值可作为初始选择，`State` 在 AF 模式中不使用；输出速度还可按信号完整性需求后续调整。

当前代码仅完成 GPIO 端口时钟和复用引脚配置，并未开启或配置 UART4 外设本身的时钟、波特率、控制寄存器。不能据 GPIO 初始化完成推断 UART 可通信。未修改源码、未编译或上板；待学习者修正基地址并提交后继续检查。

## UART 初始化参数结构体审阅

只读检查 inc/uart.h、src/uart.c。uart_init_t 当前包含 BaudRate、WordLength、Paritysel、Stopbits，属于软件配置结构体，不是寄存器映射，因此无需对应寄存器顺序或补齐所有寄存器。

- 必须能表示关闭校验：当前枚举只有 ODD/EVEN，不能表达 8-N-1。建议明确 NONE/EVEN/ODD，再由初始化函数配置 CR1.PCE 和 PS，不直接把枚举整体写入寄存器。
- UART_STOP_2_5BIT 名称错误；通用 STOP 字段相应编码表示 1.5 位，不是 2.5 位。UART4 实际可用停止位还需按实例功能限制确认；当前目标只需 1 位。

- BRR 计算必须有已确认的 UART 输入时钟，可通过参数传入或由时钟模块提供。
- uart.c 的 UART_Init() 还未声明返回类型和参数；实现前需明确接口并加入头文件原型。

## UART4 RCC 接口设计

后续纠正与简化（本节后续方案优先）：此前仅列出三个接口，缺少时钟树讲解，要求实现通用频率查询跨度较大。当前先实现 HSI 一条路径，再逐步扩展。

只读复核用户最新 rcc.h/rcc.c：UART4EN bit16 正确；RCC_MP_APB1ENSETR 地址应为 0x50000A00，当前误写成 0x40010A00；宏名 ENSTER 拼写应改为 ENSETR。置位寄存器建议直接赋掩码，函数返回 int 时补成功返回值。uart4_clock_source_e 类型仍未定义。

本地 ST CMSIS stm32mp157axx_cm4.h 的 RCC 寄存器布局与 HAL stm32mp1xx_hal_rcc_ex.h/.c 交叉核对：

- 实际时钟选择寄存器是 RCC_UART24CKSELR，USART2/UART4共用，RCC offset=0x8E8，绝对地址0x500008E8，UART24SRC字段为[2:0]。此前教师说 RCC_UART4CKSELR 不准确。
- 选源编码为0=PCLK1、1=PLL4_Q、2=HSI、3=CSI、4=HSE。改变该字段会同时影响USART2。
- HSI nominal=64MHz，UART使用的HSI还受RCC_HSICFGR.HSIDIV[1:0]影响，编码0/1/2/3分别除1/2/4/8；HAL按HSI_VALUE >> div_code计算。HSICFGR offset=0x18。
- Select函数先验证枚举、保证UART禁用和源就绪，再清UART24SRC三位并写编码；当前可仅接受HSI选源，其他编码明确返回不支持。
- Get函数检查输出指针、当前选源、HSI及分频就绪，再通过输出参数返回标称频率；不自行改变HSIDIV，不直接假定64MHz。未支持PLL/PCLK等路径必须返回错误。

仅讲解和审阅，未修改学习者驱动、编译或上板。

建议将 UART4 内核时钟源选择、APB 外设时钟使能、实际内核时钟频率查询拆成职责单一的接口，例如：

```c
int RCC_UART4_SelectClock(uart4_clock_source_e source);
int RCC_UART4_EnableClock(void);
int RCC_UART4_GetKernelClockHz(uint32_t *hz);
```

`GetKernelClockHz` 用状态返回值表达成功/失败，用输出参数提供真实频率；不要用一个只针对 UART4 的宽泛 `RCC_Init()` 暗示初始化整棵时钟树。若以后项目需要统一配置 PLL、总线分频等全局时钟，再另设全局时钟初始化函数。选择哪种 UART4 时钟源、父时钟频率是多少，须结合 RM0436 和 U-Boot/启动代码当前留下的 RCC 状态确认；不能把猜测的频率传给 UART 初始化。当前只是接口设计建议，学习者尚未实现或验证。
