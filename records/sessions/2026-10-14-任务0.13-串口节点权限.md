# 2026-10-14 任务 0.13：检查串口设备节点权限

## 当前阶段与目标

- 阶段 0：入门准备与基线。
- 本任务目标：检查板载 ST-LINK VCP 设备节点 `/dev/ttyACM0` 的文件权限和所属组，判断当前用户是否有访问权限。

## 前置证据

- FS-MP1A 板载 ST-LINK/V2.1 已通过 USB 被 Ubuntu 虚拟机枚举，USB ID `0483:374b`。
- 稳定设备链接 `...STLink...-if02` 指向 `/dev/ttyACM0`。
- 本任务只读取权限和用户组；不打开串口、不发送数据、不烧录固件。


- [x] 根据当前用户组判断访问权限；不使用 `sudo` 或修改权限。

## 学习者结果

2026-10-15，学习者提交：

```text

zgd adm cdrom sudo dip plugdev users lpadmin lxd
```

教师解读：这是字符设备，属主为 `root`，属组为 `dialout`；属主和属组均有读写权限，其他用户没有权限。提交的当前会话用户组列表不含 `dialout`，因此按所示传统权限判断，当前普通用户没有直接读写权限。未测试实际打开设备，未检查额外 ACL，未修改用户组或设备权限。

本次讲解：串口收发需要设备节点的读写权限，不需要执行权限。等待学习者解释权限判断依据。

2026-10-15，学习者回答：“当前用户不能直接读写 /dev/ttyACM0，因为其他用户没有访问权限”。结论及权限类别应用正确。教师补充完整判断链：当前用户不是属主 `root`，当前会话用户组不含 `dialout`，因此适用其他用户的 `---` 权限。本次回答未独立逐项复述属主、属组的排除过程，后续巩固。
