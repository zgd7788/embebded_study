# STM32MP157 UART4 裸机学习工程

本工程面向 FS-MP1A / STM32MP157 的 Cortex-A7，练习 UART4 时钟与 GPIO 配置、轮询收发、字符串行接收，以及串口命令控制 LED。镜像链接到 DDR 地址 `0xC0008000`，初始栈顶为 `0xC1000000`。

## 硬件连接与串口设置

- UART4_TX：PG11，AF6。
- UART4_RX：PB2，AF8。
- J1401：UART4_TX 接 11 脚、UART4_RX 接 12 脚、GND 接 13 脚。外接 USB-UART 适配器时，TX/RX 交叉连接并共地。
- SecureCRT：115200 baud、8 数据位、无校验、1 停止位、无硬件流控；关闭本地回显，以便辨认开发板发送的数据。
- LED 示例使用 GPIOZ PZ5（LED1）；按已核对的板级电路，GPIO 输出高电平点亮、低电平熄灭。

## 当前功能

- RCC 初始化：开启 UART4 外设时钟，开启并等待 HSI 就绪，选择 UART4 内核时钟源并查询频率。
- UART 配置：115200、8-N-1、16 倍过采样、PRESC 不分频、关闭硬件流控。
- 轮询发送和接收：单字节收发、字符串发送、按 CR/LF 接收一行。
- 行接收最多保存 `buf_size - 1` 个字符并添加 `\0`；超长时丢弃本行剩余字符并返回状态 2。CR 后紧跟的 LF 会在下一次读取时跳过。
- 此前命令练习使用本工程的 `strings_equal()`，避免依赖 `strcmp()` 的 C 库实现；当前该辅助函数已注释，main 用于批量接收回显。

此前已练习命令处理：`LED_ON` 设置 LED1 为亮，`LED_OFF` 设置为灭；执行后返回主接收循环，重复相同命令保持原状态。未知命令回复 `parameter error`，超长行回复 `parameter is too long`。当前 main 已暂替换为非阻塞批量接收、按实际数量逐字节回显，不执行 LED 命令。

学习者此前报告已在板上验证 UART 单字节收发以及字符串发送。2026-11-10 源码复查确认重复接收问题已修复，学习者报告已验证超长行提示及随后合法命令的恢复；其他未明确报告的边界场景不据此视为已验证。

2026-11-10 学习者报告已完成 115200 8-N-1 波形核对。初始化已加入 `FifoMode` 配置，main 选择启用 FIFO；在 UE=0 期间明确设置或清除 FIFOEN，配置源码审阅通过。学习者已验证启用 FIFO 后原有命令收发正常；专门的批量收发、FIFO容量及溢出处理练习尚未完成。

`HAL_UART4_ReadAvailable()` 已通过源码审阅：最多读取 capacity 个可用字节，FIFO 空时立即返回，实际数量由 received_out 输出，不添加字符串终止符。2026-11-10 学习者报告已验证该接口及按实际数量回显，FIFO 空时不发送旧数据；本轮未单独验证FIFO容量及溢出行为。

## 构建

在 Ubuntu 开发虚拟机中切换到本目录后执行：

```sh
make
```

默认使用 `arm-none-eabi-gcc`。产物位于 `build/`：

- `uart_putchar.elf`：链接后的 ELF。
- `uart_putchar.bin`：可由当前 U-Boot `loadb` 传输流程加载的裸二进制镜像。
- `uart_putchar.map`：链接映射文件。
- `uart_putchar.dis`：反汇编与源代码混合列表。

本工程使用 `-ffreestanding` 和 `-nostdlib`，未链接完整 C 标准库；编译器所需辅助函数通过 `-lgcc` 链接。

## 运行

先让开发板进入 U-Boot，并确认 U-Boot 已完成 DDR 初始化。按当前使用的传输流程将 BIN 放到 `0xC0008000`，再执行：

```text
go 0xC0008000
```

不要从 Linux shell 直接运行该裸机镜像；裸机程序会直接控制 GPIOZ 和 UART4，而 Linux 也可能管理这些硬件资源。

当前启动代码设置栈、清零 `.bss` 并调用 `main()`，不建立异常向量、A7 GIC 中断处理、MMU 或 Cache 配置；启动入口会屏蔽 IRQ/FIQ。程序没有看门狗刷新处理。如果 `go` 后经过固定时间复位并进入系统，看门狗是候选原因，但当前尚未确认具体复位源。

## 下一步

1. 实现非阻塞批量发送：按 TXFNF 写入，FIFO 满则返回实际提交数量；理解提交数据与 TC 表示的线上发送完成的区别。
2. 验证 FIFO 缓冲能力并学习接收溢出、帧错误、噪声和校验错误的观察、清除与恢复。
3. 按学习者最新安排，UART 轮询收尾后先学习其他外设，从定时器轮询计时开始；具备可靠时间基准后回补发送/接收等待超时，循环次数不视为毫秒。
4. 中断暂缓，后续具备 A7 异常入口与 GIC 基础后再学 UART 中断和软件环形缓冲区，不作为开始其他外设学习的前提。
5. 后续将阶段1增量协议解析库接入真实串口，覆盖拆包、连续帧、CRC与超时。DMA、硬件流控、RS-485按项目需要后学。已验证的回显与波形无需重测。外设总体安排见[外设学习路线](../../../records/labs/阶段4-外设学习路线.md)。
