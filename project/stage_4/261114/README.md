# STM32MP157 TIM2 计时与 TIM4 蜂鸣器 PWM 学习工程

本工程面向 FS-MP1A / STM32MP157 的 Cortex-A7，由此前 GPIO/UART 工程复制而来，用于学习定时器时钟、轮询计时和 PWM。当前例程由 TIM4_CH1 / PB6 / AF2 驱动扩展板蜂鸣器，约 2kHz、50% 占空比，鸣响约 500ms、静音约 500ms。TIM2 继续提供自由运行时间源，UART4 保留字符回显。本次不使用中断或 DMA。

镜像链接到 DDR 地址 `0xC0008000`，初始栈顶为 `0xC1000000`。

## 2. 为什么要追踪时钟来源

内部时钟、向上连续计数时：

~~~text
计数频率 f_CNT = f_TIM / (PSC + 1)
更新周期 T_update = (PSC + 1) × (ARR + 1) / f_TIM
~~~

`f_TIM` 是进入 TIM2 预分频器之前的内核时钟频率。只知道 TIM2 挂在 APB1 上，还不能确定这个频率；还要查 APB1 的上游来源、分频，以及定时器相对于 PCLK1 的时钟关系。

- **总线时钟**：例如 PCLK1 是 APB1 总线时钟，用于相应总线访问。
- **外设内核时钟**：驱动外设内部功能，例如 UART 收发、TIM2 计数，来源可能与总线时钟不同。
- **时钟门控**：控制是否向目标外设提供相应时钟，不负责设置输入频率。

此前 GPIO 实验主要配置、读写电平，没有根据总线频率计算精确时间，因此没有继续计算总线频率。此前 UART4 通过 `RCC_UART24CKSELR` 选择 HSI 作为内核时钟，波特率依据 HSI 及 UART 自身分频计算；如果 UART 选择 PCLK1，同样需要追踪 APB1 的频率。

本工程先读取 U-Boot 已配置好的共享时钟树，不重新设置 PLL。查询时从 TIM2 向上游反向追踪，理解后再从 HSE 向 TIM2 正向计算。

## 3. 为什么查询这些地址

RCC 管理相关时钟，基地址为 `0x50000000`。手册列出每个寄存器在 RCC 内部的偏移：

~~~text
绝对地址 = RCC 基地址 + 寄存器偏移
例如 RCC_APB1DIVR：0x50000000 + 0x834 = 0x50000834
~~~

地址用于定位寄存器；读出的 32 位值包含多个字段，必须按手册提取字段并解释编码，不能把整个读数当成分频数。

以下为学习者此前在 U-Boot 提交的实际读数，不是复位默认值：

| 寄存器 | 偏移 | 绝对地址 | 已读值 | 要解决的问题 |
|---|---|---|---|---|
| RCC_APB1DIVR | `0x834` | `0x50000834` | `0x80000001` | APB1 把上游时钟除以几？ |
| RCC_TIMG1PRER | `0x828` | `0x50000828` | `0x80000000` | TIM2 内核时钟与 PCLK1 是什么关系？ |
| RCC_MCUDIVR | `0x830` | `0x50000830` | `0x80000000` | APB1 上游的 MCU 子系统分频器除以几？ |
| RCC_MSSCKSELR | `0x048` | `0x50000048` | `0x80000003` | MCU 子系统选择了哪个时钟源？ |
| RCC_RCK3SELR | `0x820` | `0x50000820` | `0x80000001` | PLL3 选择了哪个参考输入源？ |
| RCC_PLL3CR | `0x880` | `0x50000880` | `0x00000073` | PLL3 是否开启、就绪，P 输出是否使能？ |
| RCC_PLL3CFGR1 | `0x884` | `0x50000884` | `0x01010021` | PLL3 输入分频、整数倍频各是多少？ |
| RCC_PLL3CFGR2 | `0x888` | `0x50000888` | `0x00241001` | PLL3 的 P 输出除以几？ |
| RCC_PLL3FRACR | `0x88C` | `0x5000088C` | `0x0001D020` | 是否启用小数倍频，小数部分是多少？ |

### 3.1 APB1 分频：RCC_APB1DIVR

`APB1DIV` 在 bit2～0。读数 `0x80000001` 中这个字段为 `1`，手册规定该编码表示**除以 2**：

~~~text
PCLK1 = APB1 分频器输入时钟 / 2
~~~

bit31 是就绪状态，不能参与分频数计算。到这里仍不知道输入时钟的绝对频率，需要继续向上查。

### 3.2 MCU 子系统分频：RCC_MCUDIVR

APB1 分频器的输入来自 MCU 子系统分频之后的时钟。`MCUDIV` 在 bit3～0；读数 `0x80000000` 中该字段为 `0`，编码表示**除以 1**：

~~~text
所选时钟源 → MCU 分频器 ÷1 → APB1 分频器 ÷2 → PCLK1
~~~

MCU 子系统是芯片内部的时钟域名称，不等于 A7 CPU 主频，也不要求 M4 正在执行程序。

### 3.3 MCU 子系统选源：RCC_MSSCKSELR

`MCUSSRC` 在 bit1～0，可选择 HSI、HSE、CSI 或 PLL3_P。读数 `0x80000003` 中该字段为 `3`，对应 **PLL3_P**：

~~~text
PLL3_P → MCU 分频器 ÷1 → APB1 分频器 ÷2 → PCLK1
~~~

因此才继续查看 PLL3，不是一开始就默认使用 PLL3；如果此处选 HSI，就应沿 HSI 路径查询。

### 3.4 PLL3 参考输入：RCC_RCK3SELR

`PLL3SRC` 在 bit1～0。读数 `0x80000001` 中该字段为 `1`，对应 **HSE 外部高速参考时钟**。

配套板级示例的 `stm32mp1xx_hal_conf.h` 定义 `HSE_VALUE = 24000000U`，本次采用其 **24MHz 标称值**计算，这不是独立测频结果。

## 4. PLL3 配置寄存器详解

PLL 是锁相环。本次先理解频率关系：根据参考输入，经输入分频、倍频及输出分频，得到 P 路输出。PLL3 还有 Q、R 输出，本次路径使用 P 输出。

~~~text
HSE → 除以 M → 乘以（N + 小数项）→ 除以 P → PLL3_P
~~~

下文 M、N、P 都表示解码后的实际系数，相关字段编码需要加 1。

### 4.1 RCC_PLL3CR：确认工作状态

当前读数为 `0x00000073`：

| 字段 | 位置 | 当前值 | 含义 |
|---|---|---|---|
| PLLON | bit0 | 1 | PLL3 开启 |
| PLL3RDY | bit1 | 1 | PLL3 就绪 |
| DIVPEN | bit4 | 1 | P 路输出使能 |

bit5、bit6 对应的 Q、R 输出也已使能，但不参与本次 P 路频率计算。CR 用于确认工作状态，倍分频数要从配置寄存器读取。

### 4.2 RCC_PLL3CFGR1：输入分频与整数倍频

当前读数为 `0x01010021`：

| 字段 | 位置 | 提取方法 | 编码 | 实际系数 |
|---|---|---|---|---|
| DIVM3 | bit21～16 | `(value >> 16) & 0x3F` | 1 | M = 2 |
| DIVN | bit8～0 | `value & 0x1FF` | 33，即 `0x21` | N = 34 |

所以输入先经过：

~~~text
24MHz / M = 24MHz / 2 = 12MHz
~~~

整数倍频系数为 34。当前启用了小数倍频，完整系数还要加上下一节的小数项。寄存器其余字段不属于 M/N 数值，不能直接拿整个 `0x01010021` 参与倍频计算。

### 4.3 RCC_PLL3FRACR：小数倍频

当前读数为 `0x0001D020`：

| 字段 | 位置 | 提取方法 | 当前值 |
|---|---|---|---|
| FRACLE | bit16 | `(value >> 16) & 1` | 1，小数配置使能 |
| FRACV | bit15～3 | `(value >> 3) & 0x1FFF` | 6660 |

FRACV 是 13 位字段，手册规定小数项为 `FRACV / 8192`，其中 `8192 = 2^13`。不是直接把十进制 6660 拼到整数 34 的小数点后面。

~~~text
小数项 = 6660 / 8192 = 0.81298828125
完整倍频系数 = 34 + 0.81298828125 = 34.81298828125
倍频后频率 = 12MHz × 34.81298828125 = 417.755859375MHz
~~~

当前 FRACLE 为 1，必须计入这部分；忽略小数项会把 P 输出错误地算成 204MHz。

### 4.4 RCC_PLL3CFGR2：P 输出分频

当前读数为 `0x00241001`。P 输出分频字段 `DIVP` 在 bit6～0：

~~~text
DIVP 编码 = value & 0x7F = 1
实际 P 分频系数 = 1 + 1 = 2
PLL3_P = 417.755859375MHz / 2 = 208.8779296875MHz
~~~

Q、R 分频属于其他输出，不参与本次计算。

## 5. 从 PLL3_P 算到 PCLK1 和 TIM2

### 5.1 PCLK1

~~~text
PLL3_P = 208877929.6875Hz
MCU 分频后 = PLL3_P / 1 = 208877929.6875Hz
PCLK1 = MCU 分频后 / 2 = 104438964.84375Hz
~~~

### 5.2 TIM2 与 PCLK1 的关系

`RCC_TIMG1PRER` 的 bit0 是 `TIMG1PRE`，当前读数 `0x80000000` 对应 `TIMG1PRE = 0`。倍率还必须结合 APB1 分频判断，不能无条件认为 0 就乘 2、1 就乘 4：

| APB1 实际分频系数 | TIMG1PRE = 0 | TIMG1PRE = 1 |
|---|---|---|
| 1 | 定时器时钟 = PCLK1 | 定时器时钟 = PCLK1 |
| 2 | 定时器时钟 = 2 × PCLK1 | 定时器时钟 = 2 × PCLK1 |
| 4、8、16 | 定时器时钟 = 2 × PCLK1 | 定时器时钟 = 4 × PCLK1 |

当前 APB1 除以 2，TIMG1PRE 为 0，所以：

~~~text
f_TIM2 = 2 × PCLK1 = 208877929.6875Hz ≈ 208.878MHz
~~~

这是时钟树相对于 PCLK1 的频率关系，不表示要在 TIM2 内另外配置一个 PLL。

### 5.3 当前完整时钟路径

~~~text
HSE：24MHz（板级标称参考）
  ↓ PLL3 输入除以 M=2
12MHz
  ↓ 乘以 N + FRACV/8192 = 34 + 6660/8192
417.755859375MHz
  ↓ P 路除以 P=2
PLL3_P：208.8779296875MHz
  ↓ MCUSSRC=3 选中此源，MCUDIV 除以1
208.8779296875MHz
  ↓ APB1DIV 除以2
PCLK1：104.43896484375MHz
  ↓ 当前 TIMG1PRE 与 APB1 分频组合使定时器时钟为 2×PCLK1
TIM2 内核时钟：208.8779296875MHz
  ↓ TIM2.PSC 除以 PSC+1
CNT 计数，ARR 决定计数终值和更新周期
~~~

以上频率由此前读数及 24MHz 标称参考计算，尚未物理测频。更换启动环境、修改 PLL、选源或分频后，需要重新核对，不能把该频率当作 TIM2 的固定属性。

### 5.4 时钟门控与频率配置的区别

TIM2 的 MPU 侧门控位是 `RCC_MP_APB1ENSETR.TIM2EN`，位于 bit0：

~~~text
寄存器地址 = 0x50000000 + 0xA00 = 0x50000A00
~~~

这是写 1 置位寄存器，可直接写入 `(1U << 0U)`；其他位写 0 不改变其使能状态。该操作开启 TIM2 时钟，不选择 PLL，不设置 PSC，也不启动 CNT。访问 TIM2 寄存器前应先使能时钟。

## 7. TIM2 轮询计时的学习过程（历史接口）

本节保留从 TIM2 专用接口逐步实现计时的过程。当前已改为 `GTIM_BaseInit(TIM2, ...)`、`GTIMx_Start(TIM2)` 等实例参数接口，以 `inc/gtim.h` 和第 9 节为准。

RCC 模块中的 `RCC_TIM2_EnableClock()` 及以下定时器初始化接口已经通过源码审阅：

~~~c
void TIM2_Init(uint16_t psc, uint32_t arr);
~~~

参数直接是写入 PSC、ARR 的值。当前计划使用 `psc = 20887`、`arr = 4999`：

~~~text
计数频率 = 208877929.6875 / 20888 ≈ 9999.900885Hz
更新周期 = 20888 × 5000 / 208877929.6875 ≈ 0.500004956s
~~~

理论周期约 500.005ms，微小偏差来自整数分频取整。此前假设 64MHz 时的 PSC=6399 是教学示例，不适用于当前配置。

初始化顺序：

1. 调用前先开启 TIM2 时钟；函数内部先清除 CEN，停止计数。
2. 配置内部时钟，关闭 SMCR 从模式和外部时钟模式 2。
3. 配置向上、边沿对齐、连续计数，允许更新事件。
4. 关闭中断与 DMA 请求，开启 ARR 预装载。
5. 写入 PSC 和 ARR。
6. 写 EGR.UG 产生更新，装载预分频等配置并初始化计数。
7. 按 SR 的清除语义清 UIF，初始化结束后保持停止。

`void TIM2_Start(void)` 与 `uint8_t TIM2_PollUpdate(void)` 已完成并接入 main。Start 置 CEN 开始计数；PollUpdate 不等待，UIF 为 0 返回 0，UIF 为 1 则清该标志并返回 1，main 仅在返回 1 时翻转 LED1。运行时若需保留其他 SR 状态标志，直接向 UIF 写 0、其他状态位写 1，不读改写。UIE 关闭不妨碍正常更新时 UIF 置位；中断是另一种通知 CPU 的方式。初始化产生的 UG 与正常计数到期不同，应清除初始化遗留的 UIF。

UIF 是粘滞标志，不是更新次数计数器；主循环长时间阻塞时，多个更新可能合并为一个置位状态。首次计时可先只保留 LED 与 TIM2，避免现有 UART 发送重试阻塞轮询。正常连续计数时无需每次翻转后清 CNT 或重新产生 UG。

当前 Makefile 的 `C_SRCS` 已包含 `src/gtim.c`，main 已接入定时器调用；初始化和启动在循环前各执行一次。本次教师只复查源码，硬件验证由学习者完成并报告。

### 7.1 下一项：自由运行 CNT 与经过时间

保持 PSC=20887，将 ARR 改为 `UINT32_MAX`，让 CNT 从 0 计到 0xFFFFFFFF 后自然回到 0。实现 `uint32_t TIM2_GetCounter(void)` 读取当前 CNT，不清零计数，也不等待。一个 tick 约为 100.001us，不是 1ms。

main 保存上次计数，使用无符号差值计算已经经过的 tick 数，以 `>= 5000U` 判断到期，再更新保存值并翻转 LED；不要用 `==`，CPU可能跳过恰好5000的读数。此项不再使用 PollUpdate 作为 500ms 到期依据。当前读取接口和main已通过源码审阅，新版上板验证待学习者完成。

回绕处理来自无符号数的模运算。以8位计数器为例，从250计到255、回到0再计到3，共经过9tick；数学差3-250=-247，转换为8位无符号数得到-247+256=9。32位同理，从0xFFFFFFF0到0x10，差为32-2^32，转换成uint32_t得到32。

该方法要求ARR=UINT32_MAX，使硬件回绕周期与32位无符号运算的模数2^32一致；计时中不能清零或重新初始化CNT，所计实际经过时间须小于一次完整回绕周期。两个读数无法识别额外经过的完整回绕。`UINT32_MAX`由stdint.h提供，值为0xFFFFFFFF，不需要自行定义或减1。

### 7.2 下一项：UART单字节接收超时

由学习者新增 `int HAL_UART4_GetCharTimeout(uint8_t *data_out, uint32_t timeout_ticks)`，返回0表示成功，1表示空指针，2表示超时；失败不修改输出。`timeout_ticks` 使用TIM2原始计数单位，当前10000tick约1秒，不直接称10000毫秒。调用前TIM2须已以当前PSC、ARR=UINT32_MAX自由运行启动。

函数验证参数后保存一次起始计数；循环先检查RXFNE，有数据则读RDR返回成功，否则用无符号差值判断是否达到超时。timeout_ticks=0也允许立即检查一次已有数据。不要调用旧无限等待GetChar，不要每轮重置起点或CNT。该函数仍会阻塞等待，但有时间上限；UART错误状态另行补充。main已每轮只接收一次，再按保存的返回值分支；建议保存变量使用与接口一致的int。

计时模块提供 `uint32_t Timebase_GetTicks(void)`，uart.c包含timebase.h，timebase.h仅包含stdint.h并声明接口，由timebase.c依赖gtim.h并读取TIM2计数；Makefile已加入src/timebase.c。main仍先启动时间源。接口须明确tick频率、32位回绕和运行期间不重置等前提；换底层计时实现也应保持这些契约。当前拆分源码通过，学习者已报告拆分后上板通过。

### 7.3 下一项：UART单字节发送等待超时

`int HAL_UART4_PutCharTimeout(uint8_t data, uint32_t timeout_ticks)` 已实现并通过源码审阅，记录一次起始时间，循环检查TXFNF，有空间写TDR并返回0；无空间且达到时间上限返回2，此次不写TDR。0tick允许立即检查一次空间，不调用旧的无限等待PutChar，使用timebase计时。main保存提交结果，非零时进入停止循环；成功后才等待TC，TX错误路径不调用串口打印。

此接口成功只表示字节已提交给UART，不保证最后停止位已从TX引脚发送完；TC用于判断最终传输完成，另行学习。普通UART发送通常不依赖对端程序是否读取，关闭PC串口窗口不能保证使发送FIFO填满。学习者已报告上板功能通过；未提供TX满超时分支的专门验证，不将正常回显视为该分支通过。旧PutString等无超时接口仍保留，不能据此声称全工程已消除无限等待。

### 7.4 等待TC发送完成

`int HAL_UART4_WaitTxComplete(uint32_t timeout_ticks)` 已实现并通过源码审阅，使用ISR.TC（已有UART_ISR_TC宏）。取一次起始时间，TC为1返回0，TC未置位且等待达到上限返回2，0tick允许立即检查一次。函数仅等待，不清TC、不写TDR；使用前保证UART发送已使能，timebase正常运行，没有其他代码并发写入发送数据。

main在PutCharTimeout提交成功后调用此函数，TC成功后才翻转LED。已补齐提交失败与TC等待失败时各自的停止循环；接收参数错误或非预期状态也停止处理。停止处理不会主动撤销已经提交给UART的数据。当前采用便于学习和调试的停止策略，未实现自动恢复。学习者已报告补齐处理后的版本编译上板均通过，但没有专门故障注入证据，不宣称各失败分支已实测。

提交等待与完成等待各有独立超时起点，不等于整次发送只允许一个共同预算。新增的TIM2、RCC门控、timebase、UART超时及批量收发函数已补充功能、参数、返回值和前置条件注释。旧PutString在接收超时提示中继续使用无超时发送，当前不将全工程称为已消除全部无限等待。

### 9.1 职责与状态码

通用定时器层只处理 TIM2～5，RCC 开时钟，GPIO 配引脚；蜂鸣器设备层绑定 PB6/TIM4_CH1，main 决定何时响、何时停。蜂鸣器模块独占 TIM4 的计数基础，不能与其他需要不同 PSC/ARR 的 TIM4 用户同时使用。

| 函数 | 行为 |
|---|---|
| `GTIM_BaseInit(TIMx, psc, arr)` | 配置共享计数基础，产生初始化更新，清旧状态，最后保持停止 |
| `TIM_PWM_ConfigChannel(TIMx, channel, config)` | 只配置选定通道，不改其他通道或 PSC/ARR/CNT，不启动、不产生 UG |
| `TIM_GenerateUpdate(TIMx)` | 显式触发 UG；在本例配置下装载预装载并初始化计数，影响整个定时器 |
| `TIM_ClearUpdateFlag(TIMx)` | 直接按写 0 清除规则清 UIF，保留其他状态 |
| `TIM_PWM_Start(TIMx, channel)` | 开目标 CCxE 与共享 CEN，不重置 CNT |
| `TIM_PWM_Stop(TIMx, channel)` | 只关目标 CCxE，不停止共享计数器，也不承诺引脚变为低电平 |
| `TIM_PWM_SetCompare(TIMx, channel, value)` | 只写目标 CCR；预装载使能时在下次更新事件生效，不隐式 UG |
| `TIM_SetCounter(TIMx, cnt)` | 显式改共享计数位置，不能用来重置 UART 正在依赖的 TIM2 |

新 PWM 接口返回 `0` 成功、`-1` 参数错误、`-2` 状态不允许，全部校验在硬件写入前完成。ConfigChannel 的状态错误表示 CEN 仍为 1；Start/SetCompare 的状态错误表示目标通道未处于 PWM1/2 输出模式。所有操作都要求调用方事先开启目标时钟，不能靠读取关闭时钟的寄存器进行软件校验。

TIM3/4 的 ARR/CNT/CCR 值最多 65535；TIM2/5 允许完整 32 位值。CompareValue 是原始比较值，允许超过 ARR，不表示百分比。通用驱动不维护 Init 调用历史或资源锁；BaseInit 成功、配置过程独占等前提由调用方保证。

通道映射如下，公共代码通过字段移位复用，OCxM 的高位必须一并处理：

| 通道 | CCMR | CCMR 基准移位 | CCR | CCER 基准移位 |
|---|---|---:|---|---:|
| CH1 | CCMR1 | 0 | CCR1 | 0 |
| CH2 | CCMR1 | 8 | CCR2 | 4 |
| CH3 | CCMR2 | 0 | CCR3 | 8 |
| CH4 | CCMR2 | 8 | CCR4 | 12 |

### 9.2 音调参数与启动顺序

TIM4 与 TIM2 同属 APB1 定时器组，沿用第 2～6 节已根据 U-Boot 读数推导的约 `208877929.6875Hz` 时钟。本例只开启门控，不修改 PLL3、MCU/APB1 分频或 TIMG1PRE，也未实现运行时自动查询该频率。启动环境的时钟配置若改变，以下音调和 TIM2 的 500ms 都须重新计算。

```text
PSC  = 10443，分频系数 10444
ARR  = 9，周期 10 个计数
CCR1 = 5，PWM1、高有效，占空比 50%
f_PWM = 208877929.6875 / 10444 / 10 ≈ 1999.98Hz
```

main 先开启 GPIOB 和 TIM2 时钟、初始化串口及 TIM2 时间源，再调用：

```c
RCC_TIM4_EnableClock();
Buzzer_Init();   /* 实际代码检查各返回值；初始化后 PB6 输出低，保持静音。 */
Buzzer_Start();
```

Buzzer_Init 内部先将 PB6 配为普通推挽输出低，再配置 TIM4/CH1、显式 UG 装载 CCR 并清 UIF。Buzzer_Start 开启 PWM 后把 PB6 交给 AF2；Buzzer_Stop 关闭 CH1 并把 PB6 切回普通输出低，防止只关闭 CC1E 时依赖不确定的关断电平。停止发声时 TIM4 仍计数，重新发声不保证首个脉冲完整；声响的 500ms 调度始终使用 TIM2。
